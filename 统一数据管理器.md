## 一、背景与问题

### 1.1 当前架构的问题

#### **问题1：订阅管理重复实现**

```
当前架构：
├─ MarketBoardService
│  └─ 自己管理订阅 (self.subscribed_symbols)
│
├─ DataCenterService  
│  └─ 管理网关订阅 (polling_gateway/virtual_gateway)
│
└─ 未来其他模块
   └─ 每个都要自己管理订阅 ❌ 重复！
```

#### **问题2：数据融合逻辑重复实现**

```
MarketBoardService 有完整实现 ✅
TradingGatewayService 需要类似功能 ❌
StrategyCenterService 需要类似功能 ❌
PortfolioService 需要类似功能 ❌

每个模块都要重复实现：
├─ 历史数据查询
├─ 录制数据查询
├─ 实时数据缓存
├─ 数据去重、排序、时间对齐
└─ 数据融合逻辑

代码重复：每个模块需要 500+ 行代码 ❌
```

#### **问题3：数据连续性保证机制不完善**

```
当前机制：
1. 历史数据（data_module_vnpy）- 主要数据源 ✅
2. 录制数据（vnpy_datarecorder）- 当日补充 ⚠️ 不可靠
3. 实时数据（实时缓存）- 最新Tick ✅

问题：
├─ 如果用户不recording，当日分钟级K线缺失 ❌
├─ 如果用户下午才打开，上午数据缺失 ❌
├─ 如果网络不稳定，下载失败 ❌
└─ 如果下载耗时过长，用户体验差 ❌
```

### 1.2 实时数据推送策略问题

#### **全量推送 vs 按需订阅**

```
❌ 全量推送（不推荐）
├─ 订阅全部5724个品种
├─ 资源浪费（内存、CPU、网络）
└─ 大部分数据不会被使用

✅ 按需订阅（推荐）
├─ 只订阅当前需要的品种
├─ 动态增删订阅
└─ 资源高效利用
```

#### **不同模块的订阅需求**

```
📈 行情看板模块
├─ 订阅需求：用户关注列表
├─ 订阅品种：["600000", "000001", "000002"]
└─ 订阅时机：用户打开图表时

🔄 交易网关模块
├─ 订阅需求：持仓品种 + 策略关注品种
├─ 订阅品种：current_positions + strategy_watchlist
└─ 订阅时机：策略启动时

📊 策略回测模块
├─ 订阅需求：全部品种
├─ 订阅时机：盘后回测
└─ 数据来源：历史数据（不需要实时推送）
```

## 二、设计目标

### 2.1 核心目标

```
1. 统一数据管理
   ├─ 所有模块通过统一接口获取数据
   ├─ 避免重复实现订阅和数据融合逻辑
   └─ 代码复用率提升 90%

2. 数据连续性保证
   ├─ 旧日历史数据：完整
   ├─ 当日历史数据：完整
   ├─ 实时数据：最新
   └─ 无缝融合，无缺失

3. 用户体验优化
   ├─ 数据查询快速响应
   ├─ 自动处理数据缺失
   └─ 无需用户手动干预

4. 资源高效利用
   ├─ 按需订阅，不订阅无用品种
   ├─ 智能预加载，提前准备数据
   └─ 内存和网络资源可控
```

### 2.2 非功能性目标

```
性能目标：
├─ 数据查询响应时间 < 100ms（缓存命中）
├─ 预加载时间 < 5秒（常用品种）
└─ 内存占用 < 500MB（预加载缓存）

可靠性目标：
├─ 数据完整性 100%
├─ 自动恢复机制
└─ 降级策略（网络失败时）

可维护性目标：
├─ 单一数据源
├─ 统一接口
└─ 易于测试和调试
```

## 四、数据连续性保证机制

### 4.1 数据源分类

```
┌─────────────────────────────────────────────────────────────┐
│                      数据源分类                               │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  1. 旧日历史数据（data_module_vnpy）                          │
│     ├─ 数据范围：2020-01-01 至 昨日                           │

│                                                              │
│  2. 当日历史数据（data_module_vnpy）                          │
│     ├─ 数据范围：当日已下载的分钟线                            │
│     ├─ 数据周期：1m, 5m, 15m等                                │
│     ├─ 存储位置：data/kline/{symbol}/{interval}/data.parquet │
│     ├─ 数据来源：增量下载（当日）                               │
│     └─ 完整性保证：✅ 自动下载缺失数据                           │
│                                                              │
│  3. 录制数据（vnpy_datarecorder）                             │
│     ├─ 数据范围：当日实时推送的Tick数据                         │

│     ├─ 存储位置：.vntrader/data_recorder/{date}/             │
│     ├─ 数据来源：实时推送录制                                  │
│     └─ 完整性保证：⚠️ 可选补充，不依赖                           │
│                                                              │
│  4. 实时数据（实时缓存）                                       │
│     ├─ 数据范围：最新Tick                                     │
│     ├─ 数据周期：Tick                                         │
│     ├─ 存储位置：内存缓存                                      │
│     ├─ 数据来源：实时推送                                      │
│     └─ 完整性保证：✅ 实时更新                                  │
│                                                              │
```

### 4.2 数据连续性保证原理

```
时间轴数据连续性：
┌─────────────────────────────────────────────────────────────┐
│ 2024-01-01  ｜  2024-12-18  ｜  2024-12-19  ｜  2024-12-19  │
│             ｜              ｜  上午        ｜  下午        │
└─────────────────────────────────────────────────────────────┘
      ↑              ↑              ↑              ↑
      │              │              │              │
  旧日历史数据    旧日历史数据    当日历史数据    实时数据
  (预加载)        (预加载)        (自动下载)     (实时推送)
      ✅              ✅              ✅              ✅
```

#### **保证机制1：旧日历史数据完整性**

```python
# 应用启动时检测
def check_historical_data_completeness():
    """检测旧日历史数据完整性"""
    for symbol in all_symbols:
        # 检查是否有缺失的日期
        missing_dates = detect_missing_dates(
            symbol, 
            start_date="2020-01-01", 
            end_date="yesterday"
        )
        
        if missing_dates:
            # ⚠️ 报警但不强制下载
            log_warning(f"{symbol} 缺失 {len(missing_dates)} 天数据")
            show_notification(f"品种 {symbol} 历史数据不完整，建议下载")
    
    # 不强制下载，用户可以选择性下载
    # 数据质量感知组件提供可视化
```

#### **保证机制2：当日历史数据自动下载**

```python
# 数据管理器自动下载逻辑
def get_kline_data(symbol, start, end, interval):
    """统一数据查询接口"""
    
    # 1. 检查数据完整性
    missing_ranges = check_data_completeness(symbol, start, end, interval)
    
    if missing_ranges:
        # 2. 自动下载缺失数据
        download_task = auto_download_missing_data(symbol, missing_ranges)
        
        # 3. 弹窗提示用户
        show_download_notification(
            message=f"品种 {symbol} 的历史数据正在下载，请稍等...",
            progress=download_task.progress
        )
        
        # 4. 等待下载完成
        download_task.wait_for_completion()
        
        # 5. 下载完成后继续查询
        return query_data(symbol, start, end, interval)
    
    # 数据完整，直接查询
    return query_data(symbol, start, end, interval)
```

#### **保证机制3：预加载策略**

```python
# 预加载策略（方案C - 推荐）
def start_preload_service():
    """启动预加载服务（应用启动时调用）"""
    
    # 1. 从配置文件读取常用品种
    frequently_used_symbols = load_frequently_used_symbols()
    
    # 2. 启动预加载线程
    preload_thread = threading.Thread(
        target=preload_worker,
        daemon=True,
        name="DataPreloadThread"
    )
    preload_thread.start()
    
    # 3. 预加载常用品种
    for symbol in frequently_used_symbols:
        preload_queue.append(symbol)

def preload_worker():
    """预加载工作线程"""
    while True:
        if preload_queue:
            symbol = preload_queue.pop(0)
            preload_symbol_data(symbol)
        else:
            time.sleep(5)

def preload_symbol_data(symbol):
    """预加载单个品种的数据"""
    
    # 1. 检查数据完整性
    missing_ranges = check_data_completeness(symbol)
    
    # 2. 如果有缺失，自动下载
    if missing_ranges:
        download_missing_data(symbol, missing_ranges)
    
    # 3. 查询完整数据并缓存
    data = query_complete_data(symbol)
    
    # 4. 缓存到预加载缓存
    preload_cache[symbol] = data
```

### 4.3 数据融合流程

```
┌─────────────────────────────────────────────────────────────┐
│                    数据融合流程                               │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  1. 查询旧日历史数据                                           │
│     ├─ 从预加载缓存获取（优先）                                 │
│     ├─ 或从 data_module_vnpy 查询                              │
│     └─ 数据范围：start_date 至 yesterday                       │
│                                                              │
│  2. 查询当日历史数据                                           │
│     ├─ 从 data_module_vnpy 查询                                │
│     ├─ 数据范围：today 已下载的分钟线                           │
│     └─ 如果缺失，自动下载                                       │
│                                                              │
│  3. 查询录制数据（可选）                                        │
│     ├─ 从 vnpy_datarecorder 查询                               │
│     ├─ 数据范围：today 实时推送的数据                           │
│     └─ 去重后补充到当日数据                                     │
│                                                              │
│  4. 查询实时数据                                               │
│     ├─ 从实时缓存获取                                           │
│     ├─ 数据范围：最新Tick                                       │
│     └─ 转换为K线格式                                           │
│                                                              │
│  5. 数据融合                                                   │
│     ├─ 去重：过滤重复的时间戳                                   │
│     ├─ 排序：按时间排序                                         │
│     ├─ 时间对齐：对齐到K线周期                                  │
│     └─ 返回融合后的完整数据                                     │
│                                                              │
```
