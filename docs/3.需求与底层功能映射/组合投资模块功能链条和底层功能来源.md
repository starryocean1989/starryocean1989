## 📋 模块概述

组合投资模块是星辰量化终端的投资组合管理和监控环境，提供组合创建、自动识别、实时监控和历史分析等核心功能。

### 🎯 核心定位

根据原始需求文档，组合投资界面采用**混合架构**，包含2个固有组件，无独立子界面：

**固有组件1 - 组合管理组件**:
- 展示和管理投资组合
- 数据来源：自动识别 + 用户自定义

**固有组件2 - 组合投资监控组件**:
- 实时业绩风险监控数据展示
- 点击组合管理中的网关触发

### 🔧 组合类型

**自动组合（不可删除）**:
- 策略池中激活超过1个策略的交易网关会自动展示
- 数据来源：交易网关界面的策略实例管理

**自定义组合（可删除）**:
- 用户可以自定义哪几个策略池有策略激活的网关是一个组合
- 生成虚拟网关展示在组合管理中

### 🎡 交互方式

- **选项卡展示**: 展示的交易网关本质上就是一个个的选项卡
- **点击触发**: 点击组合管理组件中的网关和虚拟网关，组合投资监控组件显示该网关（组合）的实时业绩风险监控数据
- **监控内容**: 每点击一个选项卡，右侧内容展示区展示该组合的账户实时业绩风控的综合监控和历史业绩分析

  **包定位**: VnPy投资组合管理应用，提供交易执行过程中的实时盈亏追踪和组合管理功能

  **核心功能**（可参考但不完全采用）:

  1. **PortfolioEngine（组合引擎）**:
     - 实时业绩跟踪机制
     - 基于VnPy事件引擎的订单和成交监听
     - 数据持久化（日级别持仓缓存）

  2. **实时盈亏追踪**（vnpy的核心优势）:
     - `process_trade_event(event: Event)` - 处理成交事件，实时更新持仓和盈亏
     - 基于成交事件（EVENT_TRADE）自动计算盈亏
     - 实时同步持仓变化（long_pos、short_pos）

  3. **Trading P&L vs Holding P&L分离计算**（专业财务要求）:
     - `ContractResult` 类 - 合约级别结果追踪
     - `trading_pnl`（已实现收益）：平仓产生的实际盈亏
     - `holding_pnl`（未实现收益）：持仓市值变动产生的浮动盈亏
     - `total_pnl = trading_pnl + holding_pnl`（总盈亏）
     - `calculate_pnl()` 方法 - 自动分离计算两种盈亏

  4. **按合约级别的精细化追踪**:
     - `ContractResult` 类提供每个合约的详细追踪：
       - `open_pos` - 开盘持仓
       - `last_pos` - 最新持仓
       - `long_volume` / `short_volume` - 多空成交量分离
       - `long_cost` / `short_cost` - 多空开仓成本分离
       - `trades: dict[str, TradeData]` - 所有成交记录
     - 支持多空分离的精细化管理

  5. **开仓成本管理**（准确计算已实现盈亏的关键）:
     - `update_trade(trade: TradeData)` - 更新成交并累积成本
     - 多头成本累积：`long_cost += trade.price * trade.volume * size`
     - 空头成本累积：`short_cost += trade.price * trade.volume * size`
     - 基于开仓成本准确计算平仓盈亏

  6. **定时自动刷新机制**:
     - `process_timer_event(event: Event)` - 定时刷新所有组合盈亏
     - 可配置刷新间隔（如每5秒）
     - 自动重新计算基于最新Tick价格的盈亏
     - 自动推送更新事件（EVENT_PM_PORTFOLIO）

  7. **持仓数据持久化**（日级别切换）:
     - `save_data()` - 保存组合持仓数据到JSON
     - `load_data()` - 加载历史持仓，支持跨日切换
     - 同日使用开盘持仓（open_pos）
     - 跨日时昨日收盘持仓自动成为今日开盘持仓

  8. **订单reference映射**（多组合场景必需）:
     - `order_reference_map: dict[str, str]` - 订单ID到组合reference的映射
     - `process_order_event()` - 建立订单映射
     - 确保成交能正确归属到对应组合

  9. **组合级别聚合**:
     - `PortfolioResult` 类 - 组合级别盈亏汇总
     - 自动聚合多个合约的盈亏到组合总盈亏
     - 支持多组合并行管理

  **项目实现说明**:
  - 项目采用numpy/scipy自行实现高级风险指标（VaR、CVaR、夏普比率、相关性矩阵等）
  - vnpy_portfoliomanager重点在**交易执行过程中的实时盈亏追踪**
  - 项目重点在**事后风险统计分析和绩效评估**
  - 两者功能**互补**，各有侧重：
    - vnpy_portfoliomanager优势：实时交易追踪、成本管理、盈亏分离
    - 项目自实现优势：风险度量、统计分析、虚拟网关、灵活架构

  **混合方案建议**（在项目实现基础上可选参考）:
  - ✅ 可参考vnpy_portfoliomanager的**实时盈亏计算逻辑**
  - ✅ 建议实现**Trading P&L vs Holding P&L分离**（财务报表要求）
  - ✅ 建议添加**开仓成本追踪**（准确计算已实现收益）
  - ✅ 可参考**定时自动刷新机制**（提升实时性）
  - ✅ 保留项目的**风险指标计算优势**（VaR、CVaR等高级指标）
  - ⚠️ 不建议完全替换为vnpy_portfoliomanager（架构不契合，UI不兼容）

  **为什么项目选择自行实现**:
  1. **架构契合度**：项目采用前后端分离架构，vnpy_portfoliomanager是VnPy App（包含UI）
  2. **功能定位不同**：vnpy重点是交易执行追踪，项目重点是风险统计分析
  3. **灵活性需求**：项目需要自定义虚拟网关和选项卡式界面
  4. **依赖简化**：自行实现只需numpy/scipy/pandas，vnpy需要整个VnPy生态

## 技术实现要点

### 组合投资技术架构

#### 核心架构特点

1. **混合架构设计**:
   - **固有组件1**：组合管理组件（左侧或顶部区域，始终可见）
   - **固有组件2**：组合投资监控组件（主内容区，选项卡切换）
   - **无子界面**：功能全部集成在2个固有组件中
   - **选项卡交互**：每个网关/虚拟网关对应一个选项卡

2. **自动识别机制**:
   - **实时监控**：通过vnpy事件引擎实时监控交易网关状态
   - **策略计数**：统计每个网关激活的策略数量
   - **自动触发**：策略数量>1时自动创建组合
   - **状态同步**：组合状态与网关状态实时同步

3. **虚拟网关生成**:
   - **聚合逻辑**：将多个物理网关聚合为一个虚拟网关
   - **唯一标识**：使用hashlib生成唯一的虚拟网关ID
   - **数据汇总**：汇总各成员网关的持仓、资金、交易数据
   - **统一展示**：虚拟网关与物理网关展示形式一致

4. **实时监控系统**:
   - **事件驱动**：基于vnpy事件引擎实现实时数据推送
   - **高性能计算**：使用numpy和pandas进行快速数据处理
   - **风险指标**：实时计算VaR、波动率、相关性等风险指标
   - **告警机制**：风险指标超限时自动触发告警

#### 数据流架构

1. **数据采集层**:
   - 从交易网关获取实时持仓、资金、成交数据
   - 通过vnpy事件引擎接收实时推送数据
   - 数据缓存机制提高查询效率

2. **数据处理层**:
   - 使用pandas进行数据清洗和转换
   - 使用numpy进行数值计算和矩阵运算
   - 使用scipy进行统计分析和风险计算

3. **数据展示层**:
   - React组件实时更新监控数据
   - ECharts/Recharts绘制动态图表
   - WebSocket实时推送更新数据
