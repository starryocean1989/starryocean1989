# 终端输出规范

## 概述

本文档定义了应用启动阶段的终端输出规范，确保输出清晰、一致、易读。

## 适用范围

终端输出（`print()`）仅用于以下场景：
- 应用启动前置检查
- 关键服务初始化进度
- 启动失败致命错误
- 用户主动请求的即时反馈（CLI工具、测试脚本）

**约束条件：**
- 仅在主线程startup流程使用
- 后端服务初始化完成后禁用
- UI显示后立即切换到日志系统
- 避免在QThread中使用print()

## 输出格式规范

### 1. 标题和分隔线

```python
# 主标题
print("="*70)
print("🚀 星辰金融终端 - 启动中")
print("="*70)

# 子标题
print("\n【数据库初始化】")
print("-"*50)
```

### 2. 步骤进度

使用 `[步骤 X/Y]` 格式标识进度：

```python
print("\n[步骤 1/9] 导入PySide6模块...")
print("        ✅ PySide6模块导入成功")

print("\n[步骤 2/9] 创建QApplication实例...")
print("        ✅ QApplication创建成功")
```

### 3. 状态标记

使用统一的Emoji或符号标记状态：

| 状态 | 符号 | 使用场景 |
|------|------|----------|
| 成功 | ✅ 或 [✓] | 操作成功完成 |
| 失败 | ❌ 或 [✗] | 操作失败或错误 |
| 警告 | ⚠️ 或 [!] | 警告信息或潜在问题 |
| 信息 | ℹ️ 或 [i] | 提示信息或说明 |
| 进行中 | 🔄 或 [...] | 正在进行的操作 |

### 4. 缩进规范

```python
# 主步骤：无缩进
print("[步骤 1/9] 导入PySide6模块...")

# 子步骤或详细信息：8个空格缩进
print("        ✅ PySide6模块导入成功")
print("        ℹ️  版本: 6.5.0")

# 更详细的信息：16个空格缩进
print("                模块数: 50")
```

## 完整示例

### 启动流程输出示例

```python
def main():
    """应用启动主函数."""
    print("="*70)
    print("🚀 星辰金融终端 - 启动中")
    print("="*70)
    
    # 步骤1
    print("\n[步骤 1/9] 导入PySide6模块...")
    try:
        from PySide6.QtCore import Qt
        from PySide6.QtWidgets import QApplication
        print("        ✅ PySide6模块导入成功")
    except ImportError as e:
        print(f"        ❌ PySide6导入失败: {e}")
        return 1
    
    # 步骤2
    print("\n[步骤 2/9] 创建QApplication实例...")
    app = QApplication(sys.argv)
    print("        ✅ QApplication创建成功")
    
    # 步骤3
    print("\n[步骤 3/9] 加载配置文件...")
    config_file = os.getenv("CONFIG_FILE")
    if config_file:
        print(f"        ℹ️  配置文件: {config_file}")
    else:
        print("        ℹ️  使用默认配置")
    print("        ✅ 配置加载成功")
    
    # ... 其他步骤 ...
    
    # 完成
    print("\n" + "="*70)
    print("✅ 启动成功，应用程序正在运行")
    print("="*70)
    
    return app.exec()
```

### 初始化模块输出示例

```python
def initialize_database():
    """初始化数据库."""
    print("[启动] 初始化日志数据库...")
    
    try:
        # 检查文件是否存在
        if db_path.exists():
            print("[启动]         ℹ️  数据库文件已存在，跳过创建")
            return True
        
        # 创建数据库
        print("[启动]         创建数据库文件...")
        create_database_file()
        print("[启动]         创建表结构...")
        create_tables()
        print("[启动]         创建索引...")
        create_indexes()
        
        print("[启动] ✅ 日志数据库初始化完成")
        return True
        
    except Exception as e:
        print(f"[启动] ❌ 数据库初始化失败: {e}")
        return False
```

### 错误处理输出示例

```python
try:
    result = initialize_services()
    if result["success"]:
        print("\n" + "="*70)
        print("✅ 后端服务已就绪，所有功能已激活！")
        print("="*70)
    else:
        print("\n" + "="*70)
        print(f"⚠️  后端初始化部分失败: {result['message']}")
        print("💡 UI框架仍可使用，但功能受限")
        print("="*70)
except Exception as e:
    print("\n" + "="*70)
    print(f"❌ 启动失败: {e}")
    print("="*70)
    import traceback
    traceback.print_exc()
```

## 日志切换策略

### 启动阶段使用终端输出

```python
# 启动前
print("[步骤 1/5] 初始化事件引擎...")
print("        ✅ 事件引擎初始化成功")

print("[步骤 2/5] 初始化日志系统...")
initialize_logging_system()
print("        ✅ 日志系统初始化成功")
```

### 切换到日志系统

```python
# 日志系统启动后
logger.info("数据中心服务初始化中...")
logger.info("✅ 数据中心服务初始化成功")

# 不再使用print()（除非致命错误）
```

### 混合使用示例

```python
def initialize_services():
    """初始化服务."""
    # 启动阶段：使用print
    print("[启动] 初始化后端服务...")
    
    # 初始化日志系统
    initialize_logging_system()
    print("[启动] ✅ 日志系统已就绪")
    
    # 切换到日志系统
    logger = logging.getLogger(__name__)
    logger.info("开始初始化业务服务...")
    
    # 后续只使用logger
    logger.info("初始化数据中心服务...")
    data_center = DataCenterService()
    logger.info("✅ 数据中心服务初始化成功")
    
    return {"success": True}
```

## 性能考虑

### 避免过多输出

```python
# ❌ 错误示例：循环中输出
for i in range(10000):
    print(f"处理第 {i} 条记录...")  # 性能问题

# ✅ 正确示例：批量输出
print(f"开始处理 10000 条记录...")
for i in range(10000):
    process_record(i)
    if i % 1000 == 0:
        print(f"        进度: {i}/10000")
print("✅ 处理完成")
```

## 最佳实践

1. **保持简洁**: 只输出必要的信息，避免冗余
2. **使用标记**: 统一使用Emoji或符号标记状态
3. **对齐格式**: 使用固定宽度的分隔线（70字符）
4. **及时切换**: 日志系统就绪后立即切换
5. **错误详情**: 致命错误时输出堆栈信息

## 总结

遵循本规范可以确保：
- 启动过程清晰可见
- 输出格式统一美观
- 便于问题排查
- 性能影响最小
- 用户体验友好
