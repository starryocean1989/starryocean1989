# 2. 🗃️ 数据中心界面（12个功能链条）

## 2.1 品种列表子界面（4个功能链条）

### 2.1.1 品种数据API获取链条
**功能描述**: 点击重新加载品种时，data_module_vnpy包会调用data_module_vnpy的品种列表获取方法通过外部API请求所有品种的列表，然后保存为本地缓存，然后该缓存更新到前端的品种列表栏
**技术实现**: data_module_vnpy包集成、品种列表获取方法、外部API请求接口、本地缓存管理、前端数据更新
**验收标准**: API请求成功率 ≥ 99%、品种数据获取完整、缓存保存可靠、前端更新及时

### 2.1.2 品种列表分页展示链条
**功能描述**: 品种列表界面是一个可翻页的展示列表，后端连到data_module_vnpy包生成的品种列表缓存
**技术实现**: 可翻页列表组件、分页数据加载、品种列表缓存读取、数据展示格式化
**验收标准**: 分页展示流畅、数据加载速度 ≤ 2秒、界面响应及时、展示格式正确

### 2.1.3 品种缓存快速刷新链条
**功能描述**: 刷新品种的逻辑是不调用api请求数据，只把data_module_vnpy已经生成的不同品种的列表缓存更新到前端的品种列表栏。该缓存（仅指该缓存）无失效时间，下次调用api接口请求数据时自动覆盖
**技术实现**: 本地缓存快速读取、前端数据刷新机制、缓存自动覆盖策略、无失效时间管理
**验收标准**: 刷新响应时间 ≤ 1秒、数据一致性保证、缓存覆盖机制正确、无失效时间策略有效

### 2.1.4 品种筛选与搜索链条
**功能描述**: 品种列表还应有按交易所和品种类型筛选品种的功能，该界面还应有个搜索框，搜索框的搜索范围为已筛选的品种，如不进行任何筛选则搜索框的搜索范围为所有的品种
**技术实现**: 交易所筛选器、品种类型筛选器、搜索功能组件、动态搜索范围控制、搜索结果高亮
**验收标准**: 筛选功能准确、搜索响应速度 ≤ 0.5秒、搜索范围控制正确、结果展示清晰

## 2.2 数据下载子界面（2个功能链条）

### 2.2.1 增量下载链条
**功能描述**: 数据下载界面支持增量下载一种下载模式，该组件有一个日期选择器，用户选择日期后点击增量下载按钮，调用data_module_vnpy包的K线数据增量下载方法，下载全品类（全品类指的是所有后端支持的股票，所有后端支持的可转债，T+0基金），全周期(日线，5min，1min)，用户选择日期至今的所有数据，可请求数据限制在最近100天以内
**技术实现**: data_module_vnpy的K线数据增量下载方法、日期选择器组件、下载进度监控、全品类数据管理、全周期数据处理、100天限制验证
**验收标准**: 增量下载日期选择准确、下载成功率 ≥ 95%、数据完整性验证、进度监控实时、100天限制生效

### 2.2.2 下载进度监控链条
**功能描述**: 下载进度监控，显示当前下载状态和历史下载记录
**技术实现**: 下载进度实时监控、下载状态管理、历史记录存储、任务停止控制
**验收标准**: 进度显示准确、状态更新及时、历史记录完整、停止功能可靠

## 2.3 本地数据子界面（3个功能链条）

### 2.3.1 本地数据查询链条

**功能描述**: 本地数据状态栏，该组件连接到data_module_vnpy包的数据感知方法，该方法会主动向前端同步本地数据品种质量，是否缺失

## 2.4 数据源管理子界面（3个功能链条）

### 2.4.1 轮询转推送数据源链条
**功能描述**: 数据源管理前端默认接入data_module_vnpy包的轮询转为推送的数据转换器，一旦前端点击开始，后端会分析现在的日期时间，如果是交易时间就会开始定时向API轮询并向用户推送数据，如果是非交易时间，就不轮询也不推送数据。这个数据源通过vnpy架构的gateway类型连接到数据源管理界面
**技术实现**: vnpy gateway集成、轮询转推送数据转换器、交易时间判断算法、API定时轮询、数据推送管理、连接互斥控制
**验收标准**: 交易时间判断准确、轮询频率合理、推送数据稳定、非交易时间不推送、连接互斥机制正确

### 2.4.2 虚拟推送数据源链条
**功能描述**: 虚拟实时数据推送网关，该网关前端界面应该有一个日期时间选择框，启动推送前必须配置，点击启动后会模拟从该时点推送数据，模拟过去发生的行情。这个数据源通过vnpy架构的gateway类型连接到数据源管理界面
**技术实现**: vnpy gateway集成、虚拟推送网关、日期时间选择器、历史行情模拟推送、数据回放引擎、连接互斥控制
**验收标准**: 日期时间配置必填验证、历史数据模拟推送准确、回放速度可控、数据完整性保证、连接互斥机制正确

### 2.4.3 数据源管理与录制链条
**功能描述**: 数据源管理界面有连接按钮（多个数据源互斥，只能选一个），点击后与给定数据源建立初始连接。还有一个启动/停止按钮，点击后数据源开始推送数据/停止推送数据。数据源管理界面应有状态栏，无需用户请求自动刷新数据源状态：连接断开状态/连接但未推送数据状态/数据推送状态。另外，实时数据推送时应有实时数据的recording功能，该功能无需手动启动，默认启动，但有手动关闭按钮。recording功能启动时自动录制并保存到本地缓存，保存位置可配置更改，该缓存以日为单位存在，次日会自动删除
**技术实现**: 连接管理器、互斥连接控制、启动停止控制、连接状态监控器、自动状态刷新机制、三种状态识别（断开/连接未推送/推送中）、状态展示组件、vnpy_datarecorder自动录制功能、手动关闭按钮、日级缓存管理、可配置存储路径、次日自动删除机制
**验收标准**: 连接互斥机制正确、连接建立成功率 ≥ 95%、启动停止功能可靠、状态监控实时、状态监控准确率 ≥ 99%、自动刷新及时、三种状态识别精准、状态展示清晰、自动录制功能稳定、手动关闭有效、日级缓存管理正确、存储路径配置灵活、自动删除机制可靠

**功能描述**: 交易网关界面有一个网关管理器组件，该组件布局类似于策略管理器，在内容区左侧一竖条，该组件有一个新建按钮，允许用户基于7种类型创建网关实例

**功能描述**: 点击新建后弹出表单，创建网关时选择不同的交易网关类，需要填的表单的内容也要跟着变，比如说paperaccount就不需要地址，因此你要仔细评估这些网关，分别需要用户提供哪些内容

**技术实现**: 网关实例卡片组件、连接断开控制、密码验证机制、实例删除管理
**验收标准**: 卡片展示正确、连接功能可靠、密码验证安全、删除操作完整

### 5.0.4 网关类型支持链条
**功能描述**: CTP和CTP mini 都是交易国内的期货，期权的交易网关。Sopt则是交易国内ETF期权的交易网关，tts是国内期货仿真交易网关，ib则是海外证券、期货、期权、贵金属等，paperaccount则是纯本地模拟交易网关，TDX gateway是国内股票交易网关
**技术实现**: 7种网关类型实现（CTP、CTP mini、Sopt、tts、ib、paperaccount、TDX gateway）、交易范围配置、网关特性管理
**验收标准**: 7种网关类型功能完整、交易范围配置正确、特性实现准确
