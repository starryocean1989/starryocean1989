## 2. 深化优化机会与建议

### 2.1 数据获取 / 下载链路
1. **扩展 DataFrame 原生算子覆盖范围**：现有 `dataframe_quality_counters` 与 `dataframe_to_records` 在字段缺失或类型异常时会回退到 pandas，建议新增 `native_dataframe_ops.validate_numeric`、`native_dataframe_ops.fillna_numeric` 等批量 API，确保异常列也在 C 层完成校正，减少 Python 循环与 `pd.to_numeric` 的多次遍历开销。
2. **原生品种分类/过滤算子**：分类器大量依赖 `Series.str` 前缀匹配与 `isin` 过滤，考虑在 `native_dataframe_ops` 中补充“按市场代码分段筛选”“批量前缀匹配”能力，将 `DataFrame.assign` 和 `zfill` 逻辑合并进原生流程，降低大批量品种分类时的 Python 字符串处理成本。
3. **负载均衡计算下沉**：`LoadBalancer` 目前以 Python 条件分支计算进程/协程数，可尝试引入 `native_load_balancer` 模块，将资源指标缩放、队列压力因子与服务器约束一次性在 C 层完成，减少频繁的整型运算和日志分支。

### 2.2 数据质量与缓存
1. **多指标联合扫描**：当前质量扫描对每个 DataFrame 逐条调用 pandas API，可将“重复/缺失/无效行统计 + 完整性估算”封装为单个 `native_dataframe_ops.scan_quality` 接口，直接返回 `duplicate_count`、`invalid_count`、`completeness`，避免 Python 层重复计算 `expected_bars`、`isna()`。
2. **任务队列批量入队优化**：`DownloadTaskQueue.add_tasks_batch` 在 Python 层循环调用 `put`，如能在 `native_collections` 中新增批量 `put_many` 接口，可减少锁切换并提升大批量任务入队效率。

### 2.3 监控与运行时
1. **原生进程/连接快照**：监控进程仍依赖 `psutil.process_iter` 与 `net_connections`，可新增 `native_process_metrics` 扩展（基于 Windows Pdh/NTQuery 系列 API）直接返回聚合指标，降低 Python 层遍历成本，并可在无 `psutil` 环境下保持性能一致。
2. **扩展 `native_socket_metrics`**：当前扩展仅返回缓冲区尺寸，遇到复杂场景即回退至 Python 实现。建议补充连接状态统计、缓冲区使用率及失败原因报告，避免 `psutil` 兜底路径反复遍历连接。
3. **IOCP 驱动的带宽测试**：`BandwidthMonitor`/`ServerTester` 仍以 `requests` + asyncio 执行下载，考虑复用 `native_iocp` 建立异步 HTTP 下载器（WinHTTP/WinInet 封装），既能规避 GIL，又可精准控制下载时间与取消逻辑。
4. **SMART/WMI 封装**：`SmartMonitor` 需要管理员权限并使用 WMI 逐项采集，可评估在 `native_smart` 模块中直接通过 `DeviceIoControl` 读取 S.M.A.R.T. 信息，避免 COM 开销。

### 2.4 日志与跨进程通信
1. **OrderedLogQueue 原生 flush**：当前一旦 `HighPerfPriorityQueue` 抛错即退回 Python。可在原生模块内提供“批量取出 + 回退迁移”接口，缩短降级路径。
2. **日志批量序列化**：虽然已经调用 `zero_copy_serialize`，但数据库写入仍在 Python 层拆包，可考虑在 `native_serialization` 增加日志批量打包/解包 API，结合 `native_memory` 减少多次 JSON 处理。

## 3. 推进优先级建议

| 优先级 | 候选优化 | 预估收益 | 复杂度 | 备注 |
| --- | --- | --- | --- | --- |
| 🔴 高 | `native_process_metrics` + 扩展 `native_socket_metrics` | 降低监控进程 CPU 占用、稳定 socket 指标（避免 psutil 权限异常） | 中 | 直接影响三进程稳定性与告警准确度 |
| 🔴 高 | `native_dataframe_ops.scan_quality` / `validate_numeric` | 缩短数据质量扫描与统一查询的批量处理时间 | 中 | 与现有 DataFrame 扩展保持一致，实现成本可控 |
| 🟠 中 | `native_load_balancer` / 批量入队接口 | 提升大规模下载调度的实时性 | 中-高 | 需要重新评估现有日志与防抖逻辑 |
| 🟡 次 | IOCP 带宽测试器 | 提高网络测速稳定性，避免 requests 阻塞 | 高 | 需封装 WinHTTP 或 cURL，对测试环境要求更高 |
| 🟡 次 | SMART 原生封装 | 减少 WMI 调用导致的权限与性能问题 | 高 | 涉及低层硬件调用，需评估兼容性 |

> 建议先落地高优先级项：一方面防止监控/下载链路在高负载下退化，另一方面尽快扩充 `native_dataframe_ops`，提升数据质量相关操作的确定性；其余项目可排入后续迭代并结合实际测试反馈逐步推进。
