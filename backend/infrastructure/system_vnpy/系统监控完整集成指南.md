## 🎯 核心价值

### 为什么需要这个监控系统？

| 场景 | 痛点 | 解决方案 |
|------|------|---------|
| **量化交易** | 系统卡顿影响订单执行 | 实时CPU/内存/磁盘监控 |
| **数据下载** | 不知道瓶颈在哪里 | 智能瓶颈分析和场景识别 |
| **硬件故障** | 温度过高导致宕机 | 硬件传感器监控和告警 |
| **性能优化** | 资源浪费或过载 | LoadBalancer智能负载均衡 |

### 真实案例

**案例1：数据质量扫描优化**
- **问题**：5000品种扫描需要30秒，CPU 100%，UI卡死
- **监控发现**：磁盘IO延迟150ms（瓶颈），上下文切换35000次/秒
- **LoadBalancer决策**：减少worker 50%，切换异步模型，减小批次40%
- **结果**：30秒 → 3秒（10倍提升），CPU 65%，UI流畅

**案例2：硬盘SMART预警**
- **监控发现**：重新分配扇区从0增加到5
- **告警推送**：实时推送到UI，显示"硬盘健康下降"
- **用户行动**：提前备份数据，避免数据丢失

|------|------|------|
| **操作系统** | Windows 10/11 或 Linux | ✅ 必须 |

```python
import zmq
import time
import sys

def test_integration():
    """完整集成测试."""
    print("=" * 60)
    print("System VnPy 监控系统 - 集成测试")
    print("=" * 60)

    context = zmq.Context()

    # 测试1: 数据查询（REQ/REP）
    print("\n[测试1] 数据查询（REQ/REP on 5557）...")
    try:
        req_socket = context.socket(zmq.REQ)
        req_socket.setsockopt(zmq.LINGER, 0)
        req_socket.connect("tcp://127.0.0.1:5557")
        req_socket.setsockopt(zmq.RCVTIMEO, 3000)

        req_socket.send_json({"action": "get_data"})
        data = req_socket.recv_json()

        print(f"   ✅ 数据查询成功")
        print(f"   - 时间戳: {data.get('timestamp')}")
        print(f"   - CPU: {data.get('system', {}).get('cpu_percent')}%")
        print(f"   - 内存: {data.get('system', {}).get('memory_percent')}%")
        print(f"   - 磁盘: {data.get('system', {}).get('disk_percent')}%")

        req_socket.close()
    except Exception as e:
        print(f"   ❌ 数据查询失败: {e}")
        return False

    # 测试2: 告警接收（PULL on 5555）
    print("\n[测试2] 告警接收（PULL on 5555）...")
    try:
        pull_socket = context.socket(zmq.PULL)
        pull_socket.connect("tcp://127.0.0.1:5555")
        pull_socket.setsockopt(zmq.RCVTIMEO, 5000)

        print("   - 等待告警（5秒超时）...")
        try:
            alert = pull_socket.recv_json()
            print(f"   ✅ 收到告警: {alert.get('message')}")
        except zmq.Again:
            print("   ℹ️  无告警（正常，说明系统健康）")

        pull_socket.close()
    except Exception as e:
        print(f"   ❌ 告警接收失败: {e}")
        return False

    # 测试3: 服务状态推送（PUSH on 5556）
    print("\n[测试3] 服务状态推送（PUSH on 5556）...")
    try:
        push_socket = context.socket(zmq.PUSH)
        push_socket.connect("tcp://127.0.0.1:5556")

        push_socket.send_json({
            "test_service": {
                "status": "running",
                "health": "healthy",
                "last_check": time.strftime("%Y-%m-%dT%H:%M:%S")
            }
        })
        print("   ✅ 服务状态推送成功")

        push_socket.close()
    except Exception as e:
        print(f"   ❌ 服务状态推送失败: {e}")
        return False

    # 测试4: 硬件监控
    print("\n[测试4] 硬件监控...")
    try:
        req_socket = context.socket(zmq.REQ)
        req_socket.setsockopt(zmq.LINGER, 0)
        req_socket.connect("tcp://127.0.0.1:5557")
        req_socket.setsockopt(zmq.RCVTIMEO, 3000)

        req_socket.send_json({"action": "get_data"})
        data = req_socket.recv_json()

        hardware = data.get('hardware', {})
        temp_devices = len(hardware.get('temperature', {}))

        if temp_devices > 0:
            print(f"   ✅ 硬件监控可用（检测到 {temp_devices} 个温度设备）")
            for device, sensors in hardware.get('temperature', {}).items():
                if sensors:
                    print(f"   - {device}: {sensors[0].get('current')}°C")
        else:
            print("   ⚠️  硬件监控不可用（需要LibreHardwareMonitor）")

        req_socket.close()
    except Exception as e:
        print(f"   ❌ 硬件监控测试失败: {e}")

    context.term()

    print("\n" + "=" * 60)
    print("✅ 集成测试完成！")
    print("=" * 60)
    return True

if __name__ == "__main__":

    sys.exit(0 if success else 1)
```

# 第二部分：架构设计（核心）

## 4. 为什么采用独立进程架构

### 4.1 设计演进

**V1.0 单进程架构的问题**：

```
┌────────────────────────────────────────────────────────────┐
│                       V1.0 单进程架构                        │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  主进程（单进程包含所有功能）                          │  │
│  │  ├─ 业务逻辑（交易、策略、数据）                       │  │
│  │  ├─ UI界面（PyQt）                                    │  │
│  │  └─ 监控模块 ⚠️                                       │  │
│  │     ├─ 硬件监控（需要管理员权限）                      │  │
│  │     ├─ 资源采集（可能阻塞）                            │  │
│  │     └─ 问题：崩溃会导致整个程序崩溃                    │  │
│  └──────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────┘
```

**存在的问题**：

| 问题 | 影响 | 严重度 |
|------|------|--------|
| **监控崩溃→全部崩溃** | 业务中断、交易中断 | 🔴 严重 |
| **权限提升风险** | 整个应用需要管理员权限 | 🟠 中等 |
| **性能无法隔离** | 监控开销无法独立计量和限制 | 🟡 轻微 |
| **监控阻塞主线程** | UI卡顿、用户体验差 | 🟠 中等 |
| **调试困难** | 难以定位是业务问题还是监控问题 | 🟡 轻微 |

**V2.0 独立进程架构**：

```
┌────────────────────────────────────────────────────────────────┐
│                         V2.0 独立进程架构                        │
│                                                                │
│  ┌─────────────────────────────────┐   ┌──────────────────┐   │
│  │  主进程（业务核心）              │   │  监控进程 ✅      │   │
│  │  ├─ 业务逻辑                     │   │  ├─ 指标采集    │   │
│  │  ├─ UI界面                       │   │  ├─ 告警评估    │   │
│  │  └─ SystemManagerService         │   │  └─ 数据持久化  │   │
│  │     ├─ 接收告警（缓存）          │   │                  │   │
│  │     ├─ 查询监控数据              │←──┤  ZMQ通信        │   │
│  │     └─ 看门狗（自动重启）        │──→│  (5555/5556/5557)│   │
│  └─────────────────────────────────┘   └──────────────────┘   │
│                                                                │
│  ✅ 监控进程崩溃 → 看门狗自动重启 → 业务不受影响               │
│  ✅ 只有监控进程需要管理员权限                                 │
│  ✅ 监控资源独立计量（CPU 3-4%，内存 45MB）                   │
└────────────────────────────────────────────────────────────────┘
```

### 4.2 架构收益对比

| 维度 | V1.0 单进程 | V2.0 独立进程 | 改进 |
|------|------------|--------------|------|
| **故障隔离** | ❌ 监控崩溃=全部崩溃 | ✅ 监控崩溃不影响业务 | 🎯 关键提升 |
| **资源隔离** | ❌ 无法独立计量 | ✅ CPU 3-4%，内存 45MB | 🎯 关键提升 |
| **权限隔离** | ❌ 整体需要管理员权限 | ✅ 只监控进程需要 | ⭐ 重要提升 |
| **性能优化** | ❌ 优化会影响主进程 | ✅ 独立调优 | ⭐ 重要提升 |
| **自动恢复** | ❌ 需要手动重启 | ✅ 3秒内自动恢复 | 🎯 关键提升 |
| **调试友好** | ⚠️ 难以定位问题源 | ✅ 职责明确 | ⭐ 重要提升 |

### 4.3 架构设计原则

#### 原则1：最小化耦合（松耦合通信）

```
主进程                          监控进程
   │                               │
   │  ❌ 不要：方法调用              │
   │  ❌ 不要：共享内存              │
   │  ❌ 不要：管道                  │
   │                               │
   │  ✅ 使用：ZMQ消息驱动          │
   ├───── ZMQ消息 ────────────────→│
   │                               │
   │←──── ZMQ响应 ──────────────────┤
   │                               │
```

**好处**：
- ✅ 可以独立升级监控进程（不影响主业务）
- ✅ 可以远程部署监控进程（分布式部署）
- ✅ 可以运行多个监控实例（水平扩展）
- ✅ 通信协议标准化（便于第三方集成）

#### 原则2：单向依赖

```
主进程 ──依赖──→ 监控进程
            （可选依赖）

监控进程 ✗ 不依赖 主进程
        （完全独立）
```

**实现**：
- ✅ 监控进程可以独立启动和测试
- ✅ 不需要主进程即可验证监控功能
- ✅ 主进程崩溃时监控进程继续运行
- ✅ 监控进程持续采集和持久化数据

#### 原则3：推拉结合（混合通信模式）

| 模式 | ZMQ类型 | 用途 | 频率 | 延迟 | 数据流向 |
|------|---------|------|------|------|---------|
| **推送** | PUSH/PULL | 告警通知 | 实时（事件驱动） | <100ms | 监控→主进程 |
| **查询** | REQ/REP | 监控数据 | 按需（用户触发） | <1ms | 双向 |
| **上报** | PUSH/PULL | 服务状态 | 定时（5秒） | 低优先级 | 主进程→监控 |

**为什么这样设计？**
- **告警推送**：实时性高，不能等待主进程查询
- **数据查询**：避免频繁推送大量数据，按需获取
- **状态上报**：让监控进程了解服务健康状态

#### 原则4：故障容错（多层容错机制）

```
故障场景1：监控进程崩溃
    ↓
看门狗检测（每3秒）
    ↓
自动重启（限流：3次/分钟）
    ↓
3秒内恢复正常
    ↓
主业务无感知 ✅
```

## 5. ZMQ通信架构（关键修复）

### 5.1 为什么选择ZMQ

#### 对比其他通信方式

| 方式 | 优点 | 缺点 | 适用场景 | 是否选择 |
|------|------|------|---------|---------|
| **共享内存** | 极快（ns级） | 进程耦合、不安全、难调试、不跨机器 | 高频数据交换 | ❌ |
| **管道/PIPE** | 简单 | 缓冲区64KB、易死锁、单向 | 简单日志传输 | ❌ |
| **Socket** | 标准、跨平台 | 需要自己实现协议、错误处理复杂 | 通用网络通信 | ❌ |
| **HTTP/REST** | 通用、工具多 | 需要Web服务器、开销大 | 远程API | ❌ |
| **ZMQ** | 轻量、多模式、异步、无需服务器、零拷贝 | 需要学习新API | **进程间通信** | ✅ |

#### ZMQ的核心优势

**1. 多种通信模式（开箱即用）**：
   - **REQ/REP**：请求/响应（类似HTTP，但更快）
   - **PUSH/PULL**：推送/拉取（单向数据流）
   - **PUB/SUB**：发布/订阅（一对多广播）
   - **PAIR**：点对点（双向通信）

**2. 零拷贝和异步**：
   - 消息传递零拷贝（直接共享内存指针）
   - 完全异步非阻塞（不会卡住主线程）
   - 自动处理连接和断线重连

**3. 无需中间件**：
   - 不需要消息队列服务器（如RabbitMQ）
   - 点对点直接通信
   - 部署极其简单

#### 最佳实践1：正确的Socket生命周期

```python
import zmq

def query_monitoring_data():
    """查询监控数据的正确方式."""
    context = zmq.Context()
    socket = context.socket(zmq.REQ)

    # ⚠️ 重要：设置LINGER为0，确保立即关闭
    socket.setsockopt(zmq.LINGER, 0)

    # 设置超时（避免永久阻塞）
    socket.setsockopt(zmq.RCVTIMEO, 3000)  # 接收超时3秒
    socket.setsockopt(zmq.SNDTIMEO, 3000)  # 发送超时3秒

    try:
        socket.connect("tcp://127.0.0.1:5557")
        socket.send_json({"action": "get_data"})
        response = socket.recv_json()
        return response
    except zmq.Again:
        print("❌ 查询超时")
        return None
    except Exception as e:
        print(f"❌ 查询失败: {e}")
        return None
    finally:
        # ✅ 始终关闭socket和context
        socket.close()
        context.term()
```


#### 最佳实践2：异步查询（避免阻塞UI）

```python
import threading
import zmq
import time

class MonitoringClient:
    """监控客户端（后台查询，不阻塞UI）."""

    def __init__(self):
        self.cache = {}
        self.lock = threading.Lock()
        self.running = True

        # 启动后台查询线程
        self.thread = threading.Thread(target=self._query_loop, daemon=True)
        self.thread.start()

    def _query_loop(self):
        """后台查询循环（每1秒）."""
        context = zmq.Context()
        socket = context.socket(zmq.REQ)
        socket.setsockopt(zmq.LINGER, 0)
        socket.connect("tcp://127.0.0.1:5557")
        socket.setsockopt(zmq.RCVTIMEO, 1000)  # 1秒超时

        while self.running:
            try:
                socket.send_json({"action": "get_data"})
                response = socket.recv_json()

                # 更新缓存（线程安全）
                with self.lock:
                    self.cache = response
            except zmq.Again:
                pass  # 超时，继续下次查询
            except Exception as e:
                print(f"查询失败: {e}")

            time.sleep(1)  # 每秒查询一次

        socket.close()
        context.term()

    def get_data(self):
        """获取缓存数据（UI线程调用，不阻塞）."""
        with self.lock:
            return self.cache.copy()

    def stop(self):
        """停止客户端."""
        self.running = False
        self.thread.join(timeout=2)

# UI中使用
client = MonitoringClient()

# 获取数据（不阻塞，立即返回）

cpu_percent = data.get("system", {}).get("cpu_percent", 0)
```

## 6. 事件驱动数据流

### 6.1 为什么使用事件驱动架构

**传统轮询方式的问题**：

```python
# ❌ 传统轮询方式（不推荐）
class SystemManagerUI:
    def __init__(self):
        # 每1秒查询一次
        self.timer = QTimer()
        self.timer.timeout.connect(self.update_ui)
        self.timer.start(1000)

    def update_ui(self):
        # 问题1：即使没有变化也要查询（浪费资源）
        # 问题2：查询频率固定（无法适应变化速度）
        # 问题3：阻塞UI线程（影响用户体验）
        data = self.service.query_monitoring_data()  # ZMQ查询
        self.update_display(data)
```

**存在的问题**：

| 问题 | 影响 | 解决方案 |
|------|------|---------|
| **固定轮询频率** | CPU变化快需要高频，温度变化慢可以低频 | 事件驱动，按需推送 |
| **资源浪费** | 没有变化也要查询 | 只在有数据时推送 |
| **延迟不可控** | 轮询间隔1秒，最大延迟1秒 | 实时推送，延迟<100ms |
| **UI阻塞** | 查询可能超时，阻塞UI | 事件异步接收 |

**事件驱动方式的优势**：

```python
# ✅ 事件驱动方式（推荐）
class SystemManagerUI:
    def __init__(self):
        # 订阅事件，被动接收
        self.event_engine.register(EVENT_SYSTEM_METRICS, self._on_system_metrics)

    def _on_system_metrics(self, event):
        # 优势1：实时接收（<100ms延迟）
        # 优势2：只在有数据时触发（节省资源）
        # 优势3：异步非阻塞（不影响UI）
        metrics = event.data
        QTimer.singleShot(0, lambda: self.update_display(metrics))
```

### 6.4 事件分发实现（SystemManagerService）

```python
# backend/services/system_manager_service.py
class SystemManagerService(BaseService):
    def _monitoring_push_loop(self):
        """监控数据推送循环（在后台线程运行）."""
        while self._monitoring_push_running:
            try:
                # 1. 查询监控数据（ZMQ REQ/REP）
                data = self._query_monitoring_data_safe()

                if data and "system" in data:
                    # 2. 拆分数据并分发事件
                    self._dispatch_monitoring_events(data)

                # 3. 等待2秒后再次查询
                time.sleep(2)

            except Exception as e:
                self.logger.error("监控推送循环异常: %s", e)
                time.sleep(5)

    def _dispatch_monitoring_events(self, data: Dict[str, Any]):
        """拆分监控数据并分发到不同的事件."""
        if not self.event_engine:
            return

        # 事件1: 系统指标（CPU/内存/磁盘/网络）
        if "system" in data:
            self.event_engine.put(Event(
                EVENT_SYSTEM_METRICS,
                data["system"]
            ))

        # 事件2: 硬件传感器（温度/功耗/风扇）
        if "hardware" in data and data["hardware"]:
            self.event_engine.put(Event(
                EVENT_HARDWARE_SENSORS,
                data["hardware"]
            ))

        # 事件3: 进程列表
        if "process" in data:
            self.event_engine.put(Event(
                EVENT_PROCESS_LIST,
                data["process"]
            ))

        # 事件4: SMART状态
        if "smart" in data and data["smart"]:
            self.event_engine.put(Event(
                EVENT_SMART_STATUS,
                data["smart"]
            ))

        # 事件5: 瓶颈分析
        if "analysis" in data:
            self.event_engine.put(Event(
                EVENT_BOTTLENECK_ANALYSIS,
                data["analysis"]
            ))

        # 事件6: 场景分析
        if "scenario" in data:
            self.event_engine.put(Event(
                EVENT_SCENARIO_ANALYSIS,
                data["scenario"]
```

### 6.5 事件订阅实现（SystemManagerView）

```python
# ui/modules/system_manager_view.py
class SystemManager(BaseWidget, LoggerMixin):
    """系统管理主界面."""

    # 定义线程安全的UI更新信号
    ui_update_signal = Signal(dict)  # 用于跨线程UI更新

    def __init__(self, system_service, event_engine):
        super().__init__()
        self.system_service = system_service
        self._cached_event_engine = event_engine

        # 连接UI更新信号（Qt线程安全机制）
        self.ui_update_signal.connect(self._do_throttled_ui_update)

        # 延迟事件订阅（等待EventEngine就绪）
        self._start_delayed_event_subscription()

    def _register_monitoring_events(self):
        """注册监控事件订阅."""
        if not self.event_engine:
            return False

        # ✅ 订阅系统指标事件
        self.event_engine.register(
            EVENT_SYSTEM_METRICS,
            self._on_system_metrics_event
        )

        # ✅ 订阅硬件传感器事件
        self.event_engine.register(
            EVENT_HARDWARE_SENSORS,
            self._on_hardware_sensors_event
        )

        # ✅ 订阅进程列表事件
        self.event_engine.register(
            EVENT_PROCESS_LIST,
            self._on_process_list_event
        )

        self.logger.info("✅ EventEngine已就绪，事件订阅成功")
        return True

    def _on_system_metrics_event(self, event):
        """处理系统指标事件（EventEngine工作线程调用）."""
        try:
            metrics = event.data

            # ✅ 使用Qt Signal进行线程安全的UI更新
            # 从EventEngine线程 → Qt主线程
            self.ui_update_signal.emit(metrics.copy())

        except Exception as e:
            self.logger.error("处理系统指标事件失败: %s", e)

    def _do_throttled_ui_update(self, metrics: Dict[str, Any]):
        """执行节流的UI更新（Qt主线程调用）."""
        try:
            # 节流检查：防止过度渲染
            current_time = time.time()
            time_since_last = current_time - self._last_ui_update_time

            if time_since_last < self._ui_update_interval:
                # 距离上次更新太近，跳过
                return

            # 更新UI组件
            self._update_system_status_from_data(metrics)

            # 更新时间戳
            self._last_ui_update_time = current_time

        except Exception as e:
            self.logger.error("UI更新失败: %s", e)
```

### 6.6 关键技术点：线程安全

**问题**：EventEngine的事件处理函数在**工作线程**中调用，而PyQt的UI更新必须在**主线程**中执行。

**错误做法**（会导致崩溃）：

```python
# ❌ 错误：直接在EventEngine线程中更新UI
def _on_system_metrics_event(self, event):
    metrics = event.data
    self.cpu_label.setText(f"{metrics['cpu_percent']}%")  # 崩溃！
```

**正确做法1：使用QTimer.singleShot**（早期方案）：

```python
# ⚠️ 可能不可靠：QTimer.singleShot在某些情况下可能不执行
def _on_system_metrics_event(self, event):
    metrics = event.data
    QTimer.singleShot(0, lambda m=metrics: self._update_ui(m))
```

**正确做法2：使用Qt Signal/Slot**（推荐，当前方案）：

```python
# ✅ 推荐：使用Qt的信号/槽机制（线程安全）
class SystemManager(BaseWidget):
    ui_update_signal = Signal(dict)  # 定义信号

    def __init__(self):
        super().__init__()
        # 连接信号到槽（主线程）
        self.ui_update_signal.connect(self._do_throttled_ui_update)

    def _on_system_metrics_event(self, event):
        """EventEngine线程调用."""
        metrics = event.data
        self.ui_update_signal.emit(metrics.copy())  # 发射信号

    def _do_throttled_ui_update(self, metrics):
        """Qt主线程调用（由信号自动触发）."""
        self.cpu_label.setText(f"{metrics['cpu_percent']}%")  # 安全✅
```

### 6.7 UI更新节流机制

**为什么需要节流？**

事件驱动架构下，如果事件频率过高（如每秒5次），会导致：
- UI渲染压力大（CPU占用高）
- 用户看不清快速变化的数字
- 不必要的资源浪费

**节流策略**：

```python
class SystemManager(BaseWidget):
    def __init__(self):
        super().__init__()

        # 节流配置
        self._ui_update_interval = 1.5  # 最小更新间隔1.5秒
        self._last_ui_update_time = 0.0
        self._pending_update_scheduled = False

    def _do_throttled_ui_update(self, metrics: Dict[str, Any]):
        """执行节流的UI更新."""
        try:
            # 检查距离上次更新的时间
            current_time = time.time()
            time_since_last = current_time - self._last_ui_update_time

            if time_since_last < self._ui_update_interval:
                # 跳过本次更新（节流）
                return

            # 执行UI更新
            self._update_system_status_from_data(metrics)

            # 更新时间戳
            self._last_ui_update_time = current_time

        finally:
            # ✅ 关键：确保标志位总是被重置
            self._pending_update_scheduled = False
```

**节流效果**：

| 指标 | 无节流 | 有节流（1.5秒） |
|------|--------|----------------|
| UI更新频率 | 2次/秒（跟随事件） | 0.67次/秒 |
| CPU占用 | 5-8%（UI渲染） | 2-3% |
| 用户体验 | 数字跳动太快 | 平滑可读 |

## 7. 混合并发模型

### 7.1 为什么需要混合并发

监控系统需要处理两类任务：

| 任务类型 | 特点 | 适合的并发模型 |
|---------|------|---------------|
| **快速任务** | ZMQ通信、内存计算、事件分发 | asyncio（协程） |
| **慢速任务** | 硬件传感器读取、SMART查询 | ThreadPoolExecutor（线程） |

**纯协程的问题**：

```python
# ❌ 问题：硬件采集会阻塞事件循环
async def collect_all_data():
    # 快速任务（非阻塞）
    system_data = await collect_system_metrics()  # ✅ 异步

    # 慢速任务（阻塞）
    hardware_data = get_hardware_sensors()  # ❌ 阻塞2-3秒！
    # 期间ZMQ无法响应，导致查询超时
```

**混合并发的解决方案**：

```python
# ✅ 解决：慢速任务放到线程池
async def collect_all_data():
    # 快速任务：协程
    system_data = await collect_system_metrics()

    # 慢速任务：线程池
    hardware_data = await asyncio.get_event_loop().run_in_executor(
        self.thread_pool,
        get_hardware_sensors
    )
```

```python
# backend/infrastructure/system_vnpy/monitor_system.py
class MonitoringProcessV2:
    def __init__(self):
        # asyncio事件循环
        self.loop = asyncio.new_event_loop()
        asyncio.set_event_loop(self.loop)

        # 线程池（处理阻塞任务）
        self.thread_pool = ThreadPoolExecutor(
            max_workers=4,
            thread_name_prefix="MonitorWorker"
        )

        # 监控数据缓存（协程和线程共享）
        self.monitoring_data = {}
        self.data_lock = threading.Lock()  # 线程安全

        # 协程就绪事件（启动屏障）
        self.coroutine_ready_events = {
            "zmq": asyncio.Event(),
            "fast_metrics": asyncio.Event(),
            "db_writer": asyncio.Event(),
            "alert_eval": asyncio.Event()
        }

    def run(self):
        """运行监控进程（阻塞）."""
        try:
            # 启动所有协程
            tasks = [
                self.loop.create_task(self._zmq_handler_coroutine()),
                self.loop.create_task(self._fast_metrics_coroutine()),
                self.loop.create_task(self._db_writer_coroutine()),
                self.loop.create_task(self._alert_evaluator_coroutine())
            ]

            # 等待所有协程就绪（启动屏障）
            self.loop.run_until_complete(self._wait_for_coroutines_ready())

            # 运行事件循环
            self.loop.run_forever()

        finally:
            # 清理资源
            self.thread_pool.shutdown(wait=True)
            self.loop.close()
```

**快速任务（协程）**：

```python
async def _fast_metrics_coroutine(self):
    """快速指标采集协程."""
    # 1. 设置就绪事件（启动屏障）
    self.coroutine_ready_events["fast_metrics"].set()

    while self.running:
        try:
            # 2. 采集系统指标（非阻塞）
            system_data = self.system_monitor.get_resource_usage()

            # 3. 更新缓存（线程安全）
            with self.data_lock:
                self.monitoring_data["system"] = system_data

            # 4. 异步休眠（释放事件循环）
            await asyncio.sleep(1)

        except Exception as e:
            self.logger.error("快速指标采集异常: %s", e)
            await asyncio.sleep(1)
```

**慢速任务（线程池）**：

```python
async def _hardware_metrics_coroutine(self):
    """硬件指标采集协程（慢速任务，使用线程池）."""
    self.coroutine_ready_events["hardware"].set()

    while self.running:
        try:
            # 1. 在线程池中执行阻塞任务
            hardware_data = await self.loop.run_in_executor(
                self.thread_pool,
                self._collect_hardware_data_blocking  # 阻塞函数
            )

            # 2. 更新缓存
            with self.data_lock:
                self.monitoring_data["hardware"] = hardware_data

            # 3. 异步休眠5秒
            await asyncio.sleep(5)

        except Exception as e:
            self.logger.error("硬件指标采集异常: %s", e)
            await asyncio.sleep(5)

def _collect_hardware_data_blocking(self):
    """硬件数据采集（阻塞函数，在线程池中运行）."""
    # 这个函数会阻塞2-3秒
    # 但因为在线程池中运行，不会阻塞事件循环
    return self.hardware_monitor.get_all_sensor_data()
```

### 7.4 启动屏障机制（V2.2关键修复）

**问题**：协程启动存在竞态条件，有时只启动2个协程，有时4个全部启动。

**根本原因**：
```python
# ❌ 错误：协程可能在poller.register之前就开始执行
async def _zmq_handler_coroutine(self):
    # 问题：如果这里的代码先执行，可能会阻塞
    poller = zmq.Poller()
    poller.register(self.rep_socket, zmq.POLLIN)  # 这里可能阻塞

    # 这行代码可能永远执行不到
    self.coroutine_ready_events["zmq"].set()
```

**解决方案：启动屏障**：

```python
# ✅ 正确：先设置就绪事件，再执行可能阻塞的操作
async def _zmq_handler_coroutine(self):
    # 1. 立即设置就绪事件
    self.coroutine_ready_events["zmq"].set()

    # 2. 然后执行可能阻塞的操作
    poller = zmq.Poller()
    poller.register(self.rep_socket, zmq.POLLIN)

    # 3. 主循环
    while self.running:
        ...
```

**验证启动**：

```python
async def _wait_for_coroutines_ready(self):
    """等待所有协程就绪（带超时）."""
    try:
        # 等待所有协程设置就绪事件（超时5秒）
        await asyncio.wait_for(
            asyncio.gather(*[
                event.wait()
                for event in self.coroutine_ready_events.values()
            ]),
            timeout=5.0
        )
        self.logger.info("✅ 所有协程已就绪")

    except asyncio.TimeoutError:
        self.logger.error("❌ 协程启动超时")
        raise
```

```python
def monitor_watchdog():
    """监控进程看门狗（自动重启）."""
    global monitor_process

    restart_count = 0
    restart_window_start = time.time()
    max_restarts_per_minute = 3

    logger.info("[WATCHDOG] 监控进程看门狗已启动")

    while True:
        time.sleep(3)  # 每3秒检查一次

        if monitor_process is None:
            break

        # 检查进程是否退出
        exit_code = monitor_process.poll()
        if exit_code is not None:
            logger.warning(f"[WATCHDOG] 监控进程已退出（退出码: {exit_code}）")

            # 限流：防止无限重启循环
            current_time = time.time()
            if current_time - restart_window_start > 60:
                # 重置计数器（超过1分钟）
                restart_count = 0
                restart_window_start = current_time

            restart_count += 1
            if restart_count > max_restarts_per_minute:
                logger.error(f"[WATCHDOG] ❌ 重启次数过多（{restart_count}次/分钟），停止重启")
                break

            # 等待冷却
            time.sleep(2)

            # 重启监控进程
            logger.info(f"[WATCHDOG] 正在重启监控进程（第{restart_count}次）...")
            monitor_process = start_monitor_process()
            logger.info(f"[WATCHDOG] ✅ 监控进程已重启（PID: {monitor_process.pid}）")

def main():
```

```python
# backend/services/system_manager_service.py
class SystemManagerService(BaseService):
    """系统管理服务（监控集成枢纽）."""

    def __init__(self):
        super().__init__()

        # ZMQ连接
        self._zmq_context = None
        self._zmq_push_socket = None  # 推送服务状态到监控进程
        self._zmq_pull_socket = None  # 接收告警
        self._zmq_req_socket = None   # 查询监控数据

        # 监控数据推送
        self._monitoring_push_running = False
        self._monitoring_push_thread = None

        # 告警接收
        self._alert_receiver_running = False
        self._alert_receiver_thread = None
        self.alert_cache = []  # 告警缓存
        self._alert_lock = threading.Lock()

        # ZMQ重连机制
        self._zmq_retry_counter = 0
        self._zmq_retry_interval = 5  # 5秒
        self._zmq_max_retries = 10

    def _do_initialize(self):
        """初始化服务."""
        import zmq

        # 1. 创建ZMQ上下文
        self._zmq_context = zmq.Context()

        # 2. PUSH socket: 推送服务状态到监控进程（端口5556）
        self._zmq_push_socket = self._zmq_context.socket(zmq.PUSH)
        self._zmq_push_socket.connect("tcp://127.0.0.1:5556")
        self.logger.info("✅ ZeroMQ PUSH连接到监控进程（端口5556）")

        # 3. REQ socket: 查询监控数据（端口5557）
        self._zmq_req_socket = self._zmq_context.socket(zmq.REQ)
        self._zmq_req_socket.setsockopt(zmq.LINGER, 0)
        self._zmq_req_socket.connect("tcp://127.0.0.1:5557")
        self._zmq_req_socket.setsockopt(zmq.RCVTIMEO, 1000)  # 1秒超时
        self.logger.info("✅ ZeroMQ REQ连接到监控进程（端口5557，超时1秒）")

        # 4. 测试ZMQ连接
        if self._test_zmq_connection():
            self.logger.info("✅ ZMQ连接测试成功")

            # 5. 启动监控数据推送循环
            self._start_monitoring_push_loop()
        else:
            self.logger.warning("⚠️ ZMQ连接测试失败，将自动重试")

        # 6. 启动告警接收线程
        self._start_alert_receiver()

        # 7. 启动服务状态推送定时器（Qt定时器）
        self._start_service_status_push_timer()

    def _test_zmq_connection(self):
        """测试ZMQ连接."""
        try:
            self._zmq_req_socket.send_json({"action": "health_check"})
            response = self._zmq_req_socket.recv_json()
            return response.get("status") == "healthy"
        except Exception as e:
            self.logger.error(f"ZMQ连接测试失败: {e}")
            return False

    def _start_monitoring_push_loop(self):
        """启动监控数据推送循环（后台线程）."""
        self._monitoring_push_running = True
        self._monitoring_push_thread = threading.Thread(
            target=self._monitoring_push_loop,
            name="MonitoringPushThread",
            daemon=True
        )
        self._monitoring_push_thread.start()
        self.logger.info("✅ 监控数据推送线程已启动")

    def _monitoring_push_loop(self):
        """监控数据推送循环（每2秒查询一次）."""
        while self._monitoring_push_running:
            try:
                # 1. 查询监控数据
                data = self._query_monitoring_data_safe()

                # 2. 如果查询失败，尝试重连
                if not data or "system" not in data:
                    self._zmq_retry_counter += 1

                    if self._zmq_retry_counter >= self._zmq_max_retries:
                        self.logger.warning(f"ZMQ查询失败{self._zmq_max_retries}次，尝试重连...")
                        if self._try_reconnect_zmq():
                            self._zmq_retry_counter = 0  # 重置计数器

                    time.sleep(self._zmq_retry_interval)
                    continue

                # 3. 查询成功，重置计数器
                self._zmq_retry_counter = 0

                # 4. 分发事件
                self._dispatch_monitoring_events(data)

                # 5. 等待2秒
                time.sleep(2)

            except Exception as e:
                self.logger.error(f"监控推送循环异常: {e}")
                time.sleep(5)

    def _query_monitoring_data_safe(self):
        """安全查询监控数据（带容错）."""
        try:
            # 创建临时socket（避免REQ/REP状态机问题）
            temp_socket = self._zmq_context.socket(zmq.REQ)
            temp_socket.setsockopt(zmq.LINGER, 0)
            temp_socket.connect("tcp://127.0.0.1:5557")
            temp_socket.setsockopt(zmq.RCVTIMEO, 1000)

            temp_socket.send_json({"action": "get_data"})
            data = temp_socket.recv_json()

            temp_socket.close()
            return data

        except zmq.Again:
            self.logger.debug("ZMQ查询超时")
            return {}
        except Exception as e:
            self.logger.error(f"ZMQ查询失败: {e}")
            return {}

    def _try_reconnect_zmq(self):
        """尝试重连ZMQ."""
        try:
            self.logger.info("正在重连ZMQ...")

            # 关闭旧的socket
            if self._zmq_req_socket:
                self._zmq_req_socket.close()

            # 创建新的socket
            self._zmq_req_socket = self._zmq_context.socket(zmq.REQ)
            self._zmq_req_socket.setsockopt(zmq.LINGER, 0)
            self._zmq_req_socket.connect("tcp://127.0.0.1:5557")
            self._zmq_req_socket.setsockopt(zmq.RCVTIMEO, 1000)

            # 测试连接
            if self._test_zmq_connection():
                self.logger.info("✅ ZMQ重连成功")
                return True
            else:
                self.logger.error("❌ ZMQ重连失败")
                return False

        except Exception as e:
            self.logger.error(f"ZMQ重连异常: {e}")
            return False

    def _dispatch_monitoring_events(self, data: Dict[str, Any]):
        """拆分监控数据并分发事件."""
        if not self.event_engine:
            return

        # 事件1: 系统指标
        if "system" in data:
            self.event_engine.put(Event(EVENT_SYSTEM_METRICS, data["system"]))

        # 事件2: 硬件传感器
        if "hardware" in data and data["hardware"]:
            self.event_engine.put(Event(EVENT_HARDWARE_SENSORS, data["hardware"]))

        # 事件3: 进程列表
        if "process" in data:
            self.event_engine.put(Event(EVENT_PROCESS_LIST, data["process"]))

        # 事件4: SMART状态
        if "smart" in data and data["smart"]:
            self.event_engine.put(Event(EVENT_SMART_STATUS, data["smart"]))

        # 事件5: 瓶颈分析
        if "analysis" in data:
            self.event_engine.put(Event(EVENT_BOTTLENECK_ANALYSIS, data["analysis"]))

        # 事件6: 场景分析
        if "scenario" in data:
            self.event_engine.put(Event(EVENT_SCENARIO_ANALYSIS, data["scenario"]))

    def _start_alert_receiver(self):
        """启动告警接收线程."""
        self._zmq_pull_socket = self._zmq_context.socket(zmq.PULL)
        self._zmq_pull_socket.connect("tcp://127.0.0.1:5555")
        self._zmq_pull_socket.setsockopt(zmq.RCVTIMEO, 1000)

        self._alert_receiver_running = True
        self._alert_receiver_thread = threading.Thread(
            target=self._alert_receiver_loop,
            name="AlertReceiverThread",
            daemon=True
        )
        self._alert_receiver_thread.start()
        self.logger.info("✅ 告警接收线程已启动")

    def _alert_receiver_loop(self):
        """告警接收循环."""
        while self._alert_receiver_running:
            try:
                alert = self._zmq_pull_socket.recv_json()

                # 添加到缓存
                with self._alert_lock:
                    self.alert_cache.append(alert)
                    if len(self.alert_cache) > 1000:
                        self.alert_cache = self.alert_cache[-1000:]

                # 发送事件
                if self.event_engine:
                    self.event_engine.put(Event(EVENT_SYSTEM_ALERT, alert))

            except zmq.Again:
                continue
            except Exception as e:
                self.logger.error(f"接收告警失败: {e}")

    def _start_service_status_push_timer(self):
        """启动服务状态推送定时器（Qt定时器，5秒）."""
        from PySide6.QtCore import QTimer

        self._status_push_timer = QTimer()
        self._status_push_timer.timeout.connect(self._push_service_status)
        self._status_push_timer.start(5000)  # 5秒
        self.logger.info("✅ 服务状态推送定时器已启动（Qt主线程）")

    def _push_service_status(self):
        """推送服务状态到监控进程."""
        try:
            status = self._collect_service_status()
            self._zmq_push_socket.send_json(status)
        except Exception as e:
            self.logger.error(f"推送服务状态失败: {e}")

    def _collect_service_status(self):
        """收集所有服务的状态."""
        # 从ServiceManager获取所有服务状态
        service_manager = get_service_manager()
        status = {}

        for service_name in ["data_center_service", "trading_gateway_service"]:
            service = service_manager.get_service(service_name)
            if service:
                status[service_name] = {
                    "status": "running" if service.is_initialized else "stopped",
                    "health": "healthy",
                    "last_check": time.strftime("%Y-%m-%dT%H:%M:%S")
                }

        return status

    def get_recent_alerts(self, limit=100):
        """获取最近的告警（供UI查询）."""
        with self._alert_lock:
            return self.alert_cache[-limit:]
```

### 10.1 集成架构总览

监控进程V2.5与LoadBalancer v2.3.0形成**智能资源管理闭环**：

```
监控进程（数据采集）→ SystemManagerService（事件分发）→ LoadBalancer（决策）→ 任务执行（优化）
```

**完整数据流**：

```
1. 监控进程采集资源指标（CPU/内存/磁盘/网络）
   ├─ 基础指标：cpu_percent, memory_percent, disk_percent
   └─ 子系统指标：context_switches, swap_in/out, io_latency, packet_loss

2. SystemManagerService查询并分发事件
   └─ EVENT_SYSTEM_METRICS → EventEngine

3. LoadBalancer订阅事件并评估压力
   ├─ ResourcePressureEvaluator.evaluate()
   └─ 输出：overall_pressure, bottleneck_dimension, adaptive_scale_factor

4. 执行策略决策
   ├─ ExecutionPolicy.calculate_config()
   └─ 输出：worker_count, batch_size, model, priority

5. 动态调整任务执行
   ├─ LoadBalancerQueueFacade调整配置
   └─ 实时监控反馈循环
```

```python
    """根据资源压力动态调整配置."""

    elif bottleneck == "memory":
```

## 11. 故障处理和容错

### 11.1 故障场景与处理策略

**场景1：监控进程崩溃**

```
故障现象：
└─ ZMQ查询超时（zmq.Again）
└─ UI显示监控数据停止更新

检测机制：
└─ 看门狗线程（每3秒检查monitor_process.poll()）

自动恢复：
1. 看门狗检测到进程退出
2. 等待2秒冷却
3. 重启监控进程（限流：3次/分钟）
4. 重新建立ZMQ连接
5. SystemManagerService自动重连
6. 恢复数据推送

恢复时间：3-5秒
对业务影响：✅ 无影响（主业务继续运行）
```

**场景2：ZMQ通信超时**

```
故障现象：
└─ SystemManagerService._query_monitoring_data_safe() 返回空字典
└─ _zmq_retry_counter 增加

处理策略：
1. 连续失败10次后触发ZMQ重连
2. 关闭旧socket，创建新socket
3. 重新connect到5557端口
4. 测试连接健康
5. 恢复数据查询

恢复时间：5-10秒
对业务影响：✅ 使用缓存数据降级显示
```

**场景3：EventEngine不可用**

```
故障现象：
└─ SystemManagerView._try_subscribe_events() 返回False
└─ UI日志："EventEngine尚未就绪，等待中..."

处理策略：
1. _event_subscription_timer 每秒重试
2. 检测到EventEngine可用后立即订阅
3. 停止重试定时器
4. 开始接收监控事件

恢复时间：1-5秒
对业务影响：✅ UI延迟显示监控数据
```

**场景4：UI更新节流标志卡死**

```
故障现象：
└─ _pending_update_scheduled = True 永久保持
└─ 所有后续事件被跳过

根本原因：
└─ _do_throttled_ui_update() 中的 return 语句
└─ 没有重置 _pending_update_scheduled

修复方案：
try:
    # 节流检查
    if time_since_last < self._ui_update_interval:
        return  # ❌ 提前返回，标志位未重置

    # 更新UI
    self._update_system_status_from_data(metrics)
finally:
    # ✅ 确保标志位总是被重置
    self._pending_update_scheduled = False
```
