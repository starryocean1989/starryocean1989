**告警条件**:

- 从 `monitor_system.py` 迁移到 `system_toolkit.py`

- 内部直接调用 `get_wmi_smart_monitor()`，减少跨文件引用

**使用示例**:

### 2.5 场景分析器（Part 2）

**核心类**: `ScenarioAnalyzer`

**功能**: 识别5大量化场景并提供专项优化

**方法接口**:
```python
__init__(business_metrics: Any = None)
analyze(system_metrics: Dict[str, Any], bottleneck: BottleneckResult) -> Dict[str, Any]
_identify_scenario(system_metrics: Dict[str, Any]) -> str
_analyze_bulk_download(...) -> Dict[str, Any]
_analyze_realtime_trading(...) -> Dict[str, Any]
_analyze_backtest(...) -> Dict[str, Any]
_analyze_strategy_calculation(...) -> Dict[str, Any]
_analyze_data_processing(...) -> Dict[str, Any]
```

**识别的5大场景**:
1. **bulk_download**: 批量数据下载
   - 特征：高并发数（>50）、下载进度>0、网络活跃
   - 优化维度：并发数、批次大小、异步模型、网络优化

2. **realtime_trading**: 实时交易
   - 特征：交易网关连接、订单队列>0、事件队列>0
   - 优化维度：订单响应时间、事件处理延迟、内存优化、CPU核心绑定

3. **backtest**: 策略回测
   - 特征：回测模式开启、K线计算时间>0、策略执行中
   - 优化维度：K线计算优化、策略并行化、数据缓存、内存管理

4. **strategy_calculation**: 策略计算
   - 特征：策略数量>0、指标计算时间>0
   - 优化维度：指标缓存、并行计算、算法优化

5. **data_processing**: 数据处理
   - 特征：数据库查询>0、数据处理任务>0
   - 优化维度：查询优化、批量处理、索引优化

**返回数据结构**:
```python
{
    "scenario": "bulk_download",
    "confidence": 0.95,
    "metrics": {...},
    "suggestions": ["减少并发worker 30%", ...]
}
```

### 2.6 监控进程V2（Part 3）

**核心类**: `MonitoringProcessV2`

**功能**: 混合并发架构（asyncio + 线程池）+ ZMQ通信 + 两阶段就绪

**架构特点**:
- 主事件循环（asyncio）：协程调度、ZMQ通信
- 后台线程池（ThreadPoolExecutor）：阻塞I/O操作（磁盘、WMI）
- 4个并发任务：系统监控、进程监控、硬件监控、告警评估

**初始化方法**:
```python
__init__(
    parent_pid: int,
    alert_push_port: int = 5555,
    status_pull_port: int = 5556,
    query_rep_port: int = 5557,
    bind_addr: str = "127.0.0.1"
)
```

**核心方法**:
```python
async start() -> None  # 主入口
async _initialize_components() -> None  # 两阶段初始化
async _monitor_system_task() -> None  # 系统监控协程（每1秒）
async _monitor_process_task() -> None  # 进程监控协程（每2秒）
async _monitor_hardware_task() -> None  # 硬件监控协程（每5秒）
async _evaluate_alerts_task() -> None  # 告警评估协程（每3秒）
async _handle_zmq_status_updates() -> None  # ZMQ状态接收协程
async _handle_zmq_queries() -> None  # ZMQ查询响应协程
```

**ZMQ端口**:
- 5555 (PUSH): 告警推送到主进程
- 5556 (PULL): 接收主进程服务状态
- 5557 (REP): 响应主进程查询请求

**两阶段就绪模型** (v2.6):
- Level 1 (端口就绪): ZMQ端口绑定完成，2-3秒
- Level 2 (功能完整): 硬件监控初始化完成，30-60秒（后台异步）

**查询API动作**:
```python
# 基础查询
"get_data"  # 获取所有监控数据
"get_system"  # 获取系统指标
"get_process"  # 获取进程指标
"get_hardware"  # 获取硬件传感器
"get_smart"  # 获取SMART数据
"get_bottleneck"  # 获取瓶颈分析
"get_scenario"  # 获取场景分析
"get_all"  # 获取所有数据

# 带宽测试（v2.5新增）
"get_bandwidth"  # 获取带宽信息
"test_bandwidth_full"  # 触发完整带宽测试（10-30秒）
"test_ping"  # 触发延迟测试（1-3秒）
```

**降级模式**: LibreHardwareMonitor初始化失败时，系统继续运行，硬件监控返回空数据

## 📝 关键设计模式和最佳实践

### 1. 单例模式

**使用场景**:
- `ErrorCounter`: 全局错误计数器
- `WMISmartMonitor`: WMI监控器
- `LoggingHub`: 日志Hub
- `BusinessMetricsCollector`: 业务指标采集器

**实现方式**: 双重检查锁 + 全局函数

---

### 2. 上下文管理器

**使用场景**:
- `ai_log_process`: AI流程日志
- 阶段切换（通过set_stage手动管理）

---

### 3. 混合并发模型

**架构**: asyncio主循环 + ThreadPoolExecutor后台线程

**原则**:
- I/O密集（网络、ZMQ）：asyncio协程
- CPU密集（计算）：asyncio协程
- 阻塞I/O（磁盘、WMI、COM）：后台线程池

---

### 4. 两阶段就绪模型

**问题**: 慢速组件阻塞启动流程

**解决方案**:
- Level 1: 通信层就绪（2-3秒）
- Level 2: 业务功能完整（后台异步）

---

### 5. 降级策略

**原则**: 核心功能不依赖可选组件

**实现**:
- LibreHardwareMonitor不可用 → 基础监控继续运行
- speedtest-cli不可用 → 带宽测试功能禁用
- WMI权限不足 → SMART数据标记"未知"

---

### 6. 缓存优化

**策略**:
- RuleCache: LRU + 5秒TTL
- BandwidthMonitor: 结果缓存
- AdaptiveThresholdManager: 滚动窗口统计

---

### 7. 节流机制

**策略**:
- ProgressThrottler: 500ms聚合窗口
- EventEngine节流: event_throttled目标
- 定期任务: 不同频率（1秒/2秒/3秒/5秒）
