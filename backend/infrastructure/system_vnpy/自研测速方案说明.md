# 自研网络测速方案说明

## 概述

本项目已完全移除 `speedtest-cli` 依赖，采用自研测速方案。新方案基于公共测速站点，使用纯 Python 实现，无限流风险，代码简洁，易于维护。

## 为什么移除 speedtest-cli？

### speedtest-cli 的问题

1. **限流问题严重**
   - Ookla 服务器对频繁请求进行限流（403 Forbidden）
   - 需要复杂的服务器池轮询机制（200+ 行代码）
   - 需要60秒冷却期和失败黑名单机制

2. **超时问题**
   - 没有超时机制时可能卡死47秒+
   - 需要手动设置超时参数

3. **异常值问题**
   - 偶尔返回异常大的延迟值（> 1000ms）
   - 需要额外的异常值过滤逻辑

4. **维护成本高**
   - 为了让 speedtest-cli 稳定运行，需要约200行辅助代码
   - 服务器缓存、轮询策略、健康监控等复杂逻辑

### 自研方案的优势

1. **简单**
   - 核心代码不到300行（包含完整功能）
   - 无需服务器池、轮询、冷却期等复杂机制

2. **无限流风险**
   - 使用专门的公共测速站点（Tele2、Cloudflare等）
   - 这些站点就是给人测速用的，允许高频访问

3. **稳定可靠**
   - 自动降级机制（多服务器轮询）
   - 原生超时支持（requests 库）
   - 无异常值问题

4. **易于集成**
   - 与统一日志系统（loghub）完美集成
   - 支持用户自定义配置
   - 所有日志统一路由

## 技术架构

### 核心模块

#### 1. speedtest_native.py
自研测速核心模块，提供：

```python
class NetworkSpeedTester:
    """网络测速器 - 基于公共测速站点的纯Python实现"""

    def test_latency(self, url: str) -> Dict[str, Any]:
        """测试网络延迟（HTTP HEAD请求）"""

    def test_download_speed(self, url: str) -> Dict[str, Any]:
        """测试下载速度（流式下载）"""

    def test_with_fallback(self, server_configs, test_type) -> Dict[str, Any]:
        """带降级的测速（尝试多个服务器）"""
```

#### 2. speedtest_servers.yaml
测速服务器配置文件，包含：

- **默认服务器**：Tele2、Cloudflare、ThinkBroadband等
- **国内镜像站**：阿里云、腾讯云
- **用户自定义服务器**：支持添加自己的测速服务器
- **分类管理**：global_cdn、domestic、international

## 使用说明

### 1. 配置测速服务器

编辑 `backend/infrastructure/system_vnpy/config/speedtest_servers.yaml`：

```yaml
servers:
  - name: "Tele2 瑞典"
    category: "global_cdn"
    ping_url: "http://speedtest.tele2.net/"
    download_url: "http://speedtest.tele2.net/10MB.zip"
    timeout: 15
    enabled: true

# 添加自定义服务器
custom_servers:
  - name: "我的测速服务器"
    category: "custom"
    ping_url: "http://my-server.com"
    download_url: "http://my-server.com/test.bin"
    timeout: 15
    enabled: true
```

### 2. 测速API

#### 完整带宽测试（延迟 + 下载速度）
```python
result = bandwidth_monitor.test_bandwidth_full()
# 返回:
# {
#     'download_mbps': 100.5,    # 下载速度（Mbps）
#     'upload_mbps': 0,           # 上传速度（不支持，始终为0）
#     'ping_ms': 30.2,            # 延迟（毫秒）
#     'test_time': '2025-10-30T12:00:00',
#     'test_type': 'full',
#     'server_name': 'Tele2 瑞典'
# }
```

#### 仅测试延迟（轻量级）
```python
result = bandwidth_monitor.test_ping_only()
# 返回:
# {
#     'ping_ms': 30.2,
#     'test_time': '2025-10-30T12:00:00',
#     'test_type': 'ping_only',
#     'server_name': 'Tele2 瑞典'
# }
```

### 3. 定期测速

系统会自动每5分钟执行一次延迟测试：

```python
async def _periodic_ping_test(self):
    """定期测试延迟（每5分钟，轻量级）"""
    await asyncio.sleep(300)  # 启动后5分钟开始

    while self.running:
        result = await bandwidth_monitor.test_ping_only_async()
        await asyncio.sleep(300)  # 每5分钟一次
```

## 功能限制

### 不支持上传速度测试

自研方案**不支持上传速度测试**，原因：

1. **公共测速站点限制**：大多数公共站点不提供上传测速接口
2. **实际需求有限**：大多数场景只需要下载速度和延迟
3. **代码复杂度**：实现上传测速需要额外的服务器端支持

如果确实需要上传速度测试，建议：
- 使用专门的测速服务（如自建测速服务器）
- 或保留 speedtest-cli 作为可选依赖

### 测速结果兼容性

为保持 API 兼容性，返回结果中 `upload_mbps` 字段始终为 `0`：


## 故障排查

### 问题：所有服务器测速失败

**可能原因**：
1. 网络连接问题
2. 防火墙/代理阻止
3. 测速服务器不可用

**解决方案**：
1. 检查网络连接
2. 查看日志中的具体错误信息
3. 尝试手动访问测速URL（浏览器）
4. 添加自定义测速服务器

### 问题：测速速度偏低

**可能原因**：
1. 选择的服务器距离远
2. 网络带宽本身不足
3. 测试时长太短

**解决方案**：
1. 在配置中优先使用国内服务器
2. 增加 `max_download_duration` 参数
3. 使用多次测速取平均值
