## 二、问题分析

### 2.1 核心问题

1. **日志粒度不足**: 未按场景/模块精细化控制，控制台噪音大
2. **缺少场景感知**: 启动/下载/交易阶段日志策略一致，调试困难
3. **模块未隔离**: 高频下载日志淹没策略执行日志
4. **用户角色未区分**: 开发/生产/运维模式日志需求不同

### 2.2 具体表现

- **启动阶段**: 需要详细日志排查问题，但与运行时混在一起
- **下载阶段**: 15000个任务产生300条/秒进度日志，淹没控制台
- **交易阶段**: 订单日志需要全量入库审计，但当前INFO不入库
- **调试场景**: 开发时需要DEBUG全量，生产时不需要

---

## 三、设计原则

### 3.1 核心原则

1. **分层路由**: 全局规则 → 阶段规则 → 模块规则 → 场景规则（优先级递增）
2. **用户角色感知**: 开发模式(DEBUG全量) vs 生产模式(INFO+节流) vs 运维模式(告警强化)
3. **动态策略切换**: 按生命周期阶段自动切换日志策略
4. **性能优先**: 节流+批量写入+异步分发+规则缓存
5. **可观测性**: 统计信息+日志追踪+告警联动

### 3.2 设计目标

- **减少噪音**: 控制台输出减少60%（过滤DEBUG和PROGRESS）
- **精准路由**: 不同阶段使用不同策略（启动详细、下载静默、交易全记录）
- **性能优化**: 路由耗时<0.1ms（缓存后<0.01ms），缓存命中率>95%
- **易维护**: YAML外部配置，支持热更新，无需重启

## 四、四层路由架构

### 4.1 架构图

```
应用层（任何模块）
    ↓ logging.getLogger().xxx()
LoggingHub（托管模式，唯一入口）
    ↓
RoutingRuleEngine（四层决策+缓存优化）
    ├─ Layer 4: 场景规则 (scenario_bulk_download)  ← 最高优先级
    ├─ Layer 3: 模块规则 (module_data_center)
    ├─ Layer 2: 阶段规则 (stage_downloading)
    └─ Layer 1: 全局规则 (global_defaults)         ← 最低优先级（兜底）
    ↓
RuleCache（5秒TTL缓存）
    ↓
多渠道分发
    ├─ Console (StreamHandler托管)
    ├─ File (FileHandler托管)
    ├─ Database (SQLite批量写入)
    ├─ EventEngine (VNPY事件，节流)
    ├─ UI (StatusBar/Dialog)
    └─ ZMQ (监控进程回传)
```

### 4.2 Layer 1: 全局默认规则

**用途**: 兜底规则，未被其他层覆盖时使用

**配置文件**: `config/rules_global.yaml`

**规则示例**:
```yaml
SYSTEM:
  DEBUG: [file]
  INFO: [file, console]
  WARNING: [file, console, database, event]
  ERROR: [file, console, database, event]
  CRITICAL: [file, console, database, event, ui_dialog]

PROGRESS:
  INFO: [file, event_throttled]  # 不输出到控制台
  WARNING: [file, console, event]

ALERT:
  WARNING: [file, console, database, statusbar, event]
  ERROR: [file, console, database, statusbar, ui_dialog, event]
```

**设计原则**:
- 控制台静音: DEBUG和PROGRESS.INFO不输出（减少60%噪音）
- 数据库精简: 仅WARNING+级别（减少95%存储）
- 关键弹窗: 仅ERROR+的ALERT/SYSTEM

### 4.6 路由决策流程

```python
def route(self, record: UnifiedLogRecord) -> List[str]:
    """四层路由决策"""
    # 构造缓存键
    cache_key = (log_type, level, module, scenario, current_stage)

    # 先查缓存（性能优化）
    cached = self.cache.get(cache_key)
    if cached:
        return cached

    # Layer 4: 场景规则（最高优先级）
    if scenario and scenario in scenario_rules:
        targets = scenario_rules[scenario][log_type][level]
        if targets:
            self.cache.set(cache_key, targets)
            return targets

    # Layer 3: 模块规则
    for module_config in module_rules:
        if module_matches(record.module, module_config):
            targets = module_config[log_type][level]
            if targets:
                self.cache.set(cache_key, targets)
                return targets

    # Layer 2: 阶段规则
    stage_config = stage_rules[current_stage]
    targets = stage_config.get(log_type, {}).get(level)
    if targets:
        self.cache.set(cache_key, targets)
        return targets

    # Layer 1: 全局规则（兜底）
    targets = global_rules[log_type][level]
    self.cache.set(cache_key, targets)
    return targets
```

### 5.2 RuleCache

**职责**: 规则缓存（LRU+TTL）+统计信息

**核心方法**:
```python
class RuleCache:
    def __init__(self, ttl_seconds: int = 5):
        """初始化缓存"""
        self.ttl = ttl_seconds
        self._cache: Dict[Tuple, CachedRule] = {}
        self._lock = Lock()
        self._hits = 0
        self._misses = 0

    def get(self, key: Tuple) -> Optional[List[str]]:
        """获取缓存（检查TTL）"""
        cached = self._cache.get(key)
        if cached and not self._is_expired(cached):
            self._hits += 1
            return cached.targets
        self._misses += 1
        return None

    def set(self, key: Tuple, targets: List[str]):
        """设置缓存"""
        self._cache[key] = CachedRule(
            targets=targets,
            timestamp=time.time()
        )

    def clear(self):
        """清空缓存（阶段切换时）"""
        self._cache.clear()

    def get_statistics(self) -> Dict:
        """获取统计信息"""
        total = self._hits + self._misses
        hit_rate = (self._hits / total * 100) if total > 0 else 0
        return {
            "size": len(self._cache),
            "hits": self._hits,
            "misses": self._misses,
            "hit_rate": hit_rate
        }
```

**代码位置**: `backend/infrastructure/system_vnpy/rule_cache.py`

**性能指标**:

- 缓存TTL: 5秒（阶段切换时强制清空）
- 内存占用: <10KB（约100-200个缓存项）

### 5.3 LoggingContext

**职责**: 阶段/场景上下文管理器

**核心方法**:
```python
class LoggingContext:
    def __init__(self, routing_engine: RoutingRuleEngine):
        """初始化上下文管理器"""
        self.routing_engine = routing_engine

    def set_stage(self, stage: str):
        """切换阶段（全局）"""
        self.routing_engine.set_stage(stage)

    @contextmanager
    def stage(self, stage_name: str):
        """阶段上下文（局部）"""
        old_stage = self.routing_engine.current_stage
        self.routing_engine.set_stage(stage_name)
        try:
            yield
        finally:
            self.routing_engine.set_stage(old_stage)

    @contextmanager
    def scenario(self, scenario_name: str):
        """场景上下文（通过LogRecordFactory注入）"""
        old_factory = logging.getLogRecordFactory()

        def factory(*args, **kwargs):
            record = old_factory(*args, **kwargs)
            if not hasattr(record, 'details'):
                record.details = {}
            record.details['scenario'] = scenario_name
            return record

        logging.setLogRecordFactory(factory)
        try:
            yield
        finally:
            logging.setLogRecordFactory(old_factory)

# 全局实例
def get_logging_context() -> LoggingContext:
    """获取全局上下文管理器"""
    global _logging_context
    if _logging_context is None:
        routing_engine = RoutingRuleEngine()
        _logging_context = LoggingContext(routing_engine)
    return _logging_context
```

class RuleValidator:

    VALID_LEVELS = {"DEBUG", "INFO", "WARNING", "ERROR", "CRITICAL"}

    def __init__(self, config_dir: str):

        self.errors: List[str] = []
        self.warnings: List[str] = []

## 六、性能优化策略

### 6.1 规则缓存

**机制**: LRU缓存 + 5秒TTL

**缓存键**: `(log_type, level, module, scenario, current_stage)`

**效果**:
- 路由耗时: 0.1ms → 0.01ms（10倍提升）

### 6.2 批量写入

**机制**:
- 批量大小: 10条
- 强制刷新: 5秒
- 关闭时刷新: 确保不丢失

**效果**: 数据库写入频率降低90%

### 6.3 节流机制

**适用**: PROGRESS类型的INFO级别日志

**机制**: 500ms聚合窗口

**效果**: 300条/秒 → 2条/秒（减少99.3%）

### 6.4 分级存储

**策略**:
- 控制台: 仅SYSTEM/NOTIFICATION/ALERT的INFO+级别
- 文件: 所有级别（DEBUG到CRITICAL）
- 数据库: 仅WARNING+级别
- EventEngine: 进度、通知、告警

**效果**: 数据库日志数量减少95%

## 二、YAML配置详解

### 2.1 rules_global.yaml（全局默认规则）

**用途**: 兜底规则，未被其他层覆盖时使用

**配置示例**:
```yaml
SYSTEM:
  DEBUG: [file]
  INFO: [file, console]
  WARNING: [file, console, database, event]
  ERROR: [file, console, database, event]
  CRITICAL: [file, console, database, event, ui_dialog]

PROGRESS:
  INFO: [file, event_throttled]  # 不输出到控制台
  WARNING: [file, console, event]
  ERROR: [file, console, database, event]

NOTIFICATION:
  INFO: [file, console, statusbar, event]
  WARNING: [file, console, database, event]
  ERROR: [file, console, database, event]

ALERT:
  WARNING: [file, console, database, statusbar, event]
  ERROR: [file, console, database, statusbar, ui_dialog, event]
  CRITICAL: [file, console, database, statusbar, ui_dialog, event]

USER_FEEDBACK:
  INFO: [statusbar]
  ERROR: [ui_dialog]

DEBUG:
  DEBUG: [file]
```

**设计原则**:
- 控制台静音: DEBUG和PROGRESS.INFO不输出（减少60%噪音）
- 数据库精简: 仅WARNING+级别（减少95%存储）
- 关键弹窗: 仅ERROR+的ALERT/SYSTEM

## 六、故障排查指南

### 问题1: 配置验证失败

**症状**: 启动时提示"路由规则配置验证失败"

**排查步骤**:
1. 运行`rule_validator.py`查看详细错误
   ```bash
   python backend/infrastructure/system_vnpy/rule_validator.py
   ```
2. 检查YAML语法（缩进、冒号、引号）
3. 检查日志类型/级别/目标是否合法

### 问题2: 路由引擎初始化失败

**症状**: 日志显示"路由引擎初始化失败: xxx"

**排查步骤**:
1. 检查config目录是否存在
2. 检查4个YAML文件是否存在
3. 检查YAML文件是否可读（权限）

### 问题3: 阶段切换不生效

**症状**: 调用set_stage后，日志输出未改变

**排查步骤**:
1. 检查是否正确获取LoggingHub实例
2. 检查stage名称是否正确（与YAML中一致）
3. 检查缓存是否清空（阶段切换会自动清空）

### 问题4: 场景上下文不生效

**症状**: 使用场景上下文后，仍使用全局规则

**排查步骤**:
1. 检查scenario名称是否正确（不带`scenario_`前缀）
2. 检查YAML中是否定义了该场景规则
3. 检查场景规则是否正确配置

### 问题5: 性能不达标

**症状**: 路由耗时>0.1ms或缓存命中率<95%

**排查步骤**:
1. 检查缓存TTL设置（默认5秒）
2. 检查是否频繁切换阶段（会清空缓存）
3. 运行性能测试脚本，查看详细统计
