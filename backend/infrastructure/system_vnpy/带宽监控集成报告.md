## 📝 关键设计决策

### 1. 分离测试类型

- **完整测试**（重量级）:
  - 包含：下载速度 + 上传速度 + 延迟
  - 耗时：10-30秒
  - 触发：启动时1次 + 手动触发
  - 用途：了解完整带宽能力

- **延迟测试**（轻量级）:
  - 包含：仅延迟（ping）
  - 耗时：1-3秒
  - 触发：定期执行（每5分钟）+ 手动触发
  - 用途：持续监控网络质量

### 2. 异步执行

所有测速操作都使用 `asyncio.to_thread` 在独立线程中执行，避免阻塞事件循环。

### 3. 启动延迟

- 完整测试：启动后延迟5秒执行，避免影响主进程启动
- 延迟测试：启动后延迟1分钟开始，然后每5分钟执行一次

### 4. 结果缓存

- 完整测试和延迟测试的结果分别缓存
- 通过 `get_bandwidth` API 可随时获取最新缓存结果
- 缓存包含测试时间戳，便于判断数据新鲜度

### 5. 独立监控指标

带宽测试作为独立监控指标，不集成到告警系统。用户可以通过API获取数据后自行处理。

## 📌 注意事项

### 1. 性能影响

- **完整测试**：占用带宽，建议在非高峰期或手动触发
- **延迟测试**：几乎无影响，可频繁执行

### 2. 网络环境

- 测速需要网络连接
- 防火墙可能阻止测速
- VPN/代理可能影响测速结果

### 3. 依赖检查

如果 `speedtest-cli` 未安装：
- 系统会在启动时警告
- 带宽测试功能不可用
- 其他监控功能正常工作
- 调用API会返回 None 或错误信息

### 4. 并发限制

- 同一时间只能执行一个测速任务
- 如果测试正在进行中，新的测试请求会被忽略
