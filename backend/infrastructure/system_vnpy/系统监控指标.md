## 设计思路

### 量化金融5大核心场景

| 场景 | 主要瓶颈 | 关键指标 |
|------|---------|---------|
| **数据下载** | 网络带宽、磁盘I/O | 网络速度、磁盘写入、I/O延迟 |
| **实时行情** | 网络延迟、数据处理 | 网络丢包、事件队列、上下文切换 |
| **策略回测** | CPU计算、内存 | CPU使用率、内存泄漏、交换活动 |
| **策略编写** | IDE响应、编译 | CPU单核性能、内存可用量 |
| **实盘交易** | 延迟、稳定性 | 网络延迟、CPU温度、系统稳定性 |

### 指标删减原则

**删除的指标类型**：
1. **冗余指标**：上下文切换已能反映调度压力，syscalls_per_sec删除
2. **相关指标链**：network_sent/recv是累计值，只监控speed即可
3. **不会成为瓶颈**：
   - CPU频率（现代CPU自动boost）
   - 风扇转速（不影响性能，只是散热）
   - 电压（硬件自动调节）
   - 启动/停止次数（与性能无关）
4. **平台限制**：steal_time（仅虚拟机），page_faults（跨平台不可得）
5. **冗余派生**：磁盘I/O总速度（=read+write）、网络总速度（同理）

**保留的指标**：
- 直接影响性能的瓶颈指标
- 可操作的优化指标
- 量化场景的关键指标

### 新增的量化特定指标

**业务性能指标**（8个）：
- 事件处理延迟
- 订单响应时间
- K线计算延迟
- 策略执行周期
- 数据查询延迟
- WebSocket消息积压
- 交易队列长度
- 数据库连接池

## 瓶颈分析模型

### 木桶理论模型

```
性能 = min(CPU性能, 内存性能, 磁盘I/O性能, 网络性能)
```

**评分规则**：
- 每个维度评分 0-100
- 系统性能 = 最低分（木桶短板）
- 瓶颈 = 评分最低的维度

### 压力评分公式

```python
# CPU压力 (40分满分)
cpu_score = 40 × (1 - cpu_percent/100) × (1 - context_switches/100000)

# 内存压力 (30分满分)
memory_score = 30 × (1 - memory_percent/100) × (1 if swap==0 else 0)

# 磁盘压力 (15分满分)
disk_score = 15 × (1 - io_latency/50)

# 网络压力 (15分满分)
network_score = 15 × (1 - packet_loss/0.05) × (1 - latency/100)

# 总分
total_score = cpu_score + memory_score + disk_score + network_score
```

**瓶颈判断**：
- 85-100分：性能充足
- 70-85分：正常
- 50-70分：压力大
- <50分：瓶颈

## 核心指标清单

### 一、系统资源指标（12个）

#### 瞬时阈值指标（8个）

**1. cpu_percent** ⭐⭐⭐
- **说明**: CPU总使用率
- **阈值**: 警告>80%, 严重>90%
- **场景**: 回测、实时策略计算
- **调优**: 降低并发、优化算法复杂度

**2. memory_percent** ⭐⭐⭐
- **说明**: 内存使用率
- **阈值**: 警告>80%, 严重>90%
- **场景**: 大数据回测、多策略并行
- **调优**: 减少数据缓存、释放无用对象

**3. swap_in_kbps** ⭐⭐⭐ (最严重)
- **说明**: 内存换入速度
- **阈值**: 严重>0
- **影响**: 性能下降100-1000倍
- **紧急措施**: 立即降低负载50%

**4. swap_out_kbps** ⭐⭐⭐ (最严重)
- **说明**: 内存换出速度
- **阈值**: 严重>0
- **调优**: 同swap_in

**5. context_switches_per_sec** ⭐⭐⭐
- **说明**: 上下文切换频率
- **阈值**: 警告>50000, 严重>100000
- **场景**: 实时行情处理（高并发）
- **调优**: 减少线程数、使用协程

**6. average_io_latency_ms** ⭐⭐
- **说明**: 磁盘I/O平均延迟
- **阈值**: 正常<10ms, 瓶颈>20ms
- **场景**: 数据下载、历史数据加载
- **调优**: 使用SSD、减少I/O操作

**7. packet_loss_rate** ⭐⭐
- **说明**: 网络丢包率
- **阈值**: 警告>0.5%, 严重>2%
- **场景**: 实时行情订阅、交易指令
- **调优**: 检查网络质量、切换服务器

**8. disk_percent**
- **说明**: 磁盘空间使用率
- **阈值**: 警告>85%, 严重>95%
- **场景**: 历史数据存储
- **调优**: 清理日志、压缩数据

#### 时间趋势指标（4个）

**9. memory_percent (趋势)**
- **用途**: 内存泄漏检测
- **分析**: 持续上升>5%/小时
- **场景**: 长时间运行的策略

**10. disk_io_speed (read/write)**
- **用途**: I/O负载模式分析
- **分析**: 峰值模式、持续高负载
- **场景**: 数据下载、回测

**11. network_speed (upload/download)**
- **用途**: 带宽使用模式
- **分析**: 是否达到带宽上限
- **场景**: 实时行情、数据同步

**12. cpu_percent (趋势)**
- **用途**: 负载模式分析
- **分析**: 突增、周期性波动
- **场景**: 定时任务、策略周期

## 监控策略

### 瞬时阈值策略（27个指标）

**告警级别**：
```python
def evaluate_threshold(value, thresholds):
    if value > thresholds['critical']:
        return 'CRITICAL'  # 立即处理
    elif value > thresholds['warning']:
        return 'WARNING'   # 需要关注
    else:
        return 'NORMAL'
```

**关键阈值配置**：
```json
{
  "swap_activity": {"warning": 0, "critical": 1000},
  "context_switches": {"warning": 50000, "critical": 100000},
  "io_latency_ms": {"warning": 10, "critical": 20},
  "packet_loss": {"warning": 0.005, "critical": 0.02},
  "event_queue": {"warning": 1000, "critical": 5000},
  "order_response_ms": {"warning": 500, "critical": 1000}
}
```

### 时间趋势策略（20个指标）

**分析方法**：
1. **线性回归**：检测持续趋势（内存泄漏）
2. **移动平均**：平滑噪声
3. **异常检测**：3σ原则、MAD
4. **基线对比**：与历史P50/P95对比

**示例**：
```python
# 内存泄漏检测
def detect_memory_leak(memory_history_1h):
    slope = linear_regression(memory_history_1h).slope
    if slope > 0.05:  # 每小时增长>5%
        return True, f"内存泄漏：每小时增长{slope*100:.1f}%"
    return False, "正常"

# 性能衰退检测
def detect_performance_degradation(latency_history_7d):
    baseline_p95 = np.percentile(latency_history_7d[:24*7], 95)
    current_p95 = np.percentile(latency_history_7d[-24:], 95)
    degradation = (current_p95 / baseline_p95 - 1) * 100
    if degradation > 20:
        return True, f"性能下降{degradation:.1f}%"
    return False, "正常"
```

|---------|---------|---------|

| 业务性能 | 1秒 | 同上 |

## API接口

### ZMQ获取监控数据

```python
import zmq
import json

ctx = zmq.Context()
socket = ctx.socket(zmq.REQ)
socket.connect('tcp://127.0.0.1:5557')

# 获取完整数据
socket.send_json({'action': 'get_data'})
data = socket.recv_json()

# 核心指标提取
system = data['system']
bottleneck = {
    'cpu_percent': system['cpu_percent'],
    'memory_percent': system['memory_percent'],
    'swap_in': system['memory_subsystem']['swap_in_kbps'],
    'context_switches': system['cpu_detailed']['context_switches_per_sec'],
    'io_latency': system['storage_subsystem']['disks']['PhysicalDrive0']['average_io_latency_ms'],
    'packet_loss': system['network_subsystem']['packet_loss_rate_in']
}

# 计算压力评分
def calculate_pressure_score(metrics):
    cpu_score = 40 * (1 - metrics['cpu_percent']/100) * (1 - metrics['context_switches']/100000)
    memory_score = 30 * (1 - metrics['memory_percent']/100) * (1 if metrics['swap_in']==0 else 0)
    disk_score = 15 * (1 - metrics['io_latency']/50)
    network_score = 15 * (1 - metrics['packet_loss']/0.05)

    total = cpu_score + memory_score + disk_score + network_score

    # 找出瓶颈
    scores = {
        'cpu': cpu_score,
        'memory': memory_score,
        'disk': disk_score,
        'network': network_score
    }
    bottleneck_dim = min(scores, key=scores.get)

    return {
        'total_score': total,
        'bottleneck': bottleneck_dim,
        'scores': scores
    }
```

- `voltage`: 非瓶颈
