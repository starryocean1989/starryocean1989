## 一、系统概述

### 1.1 设计目标

统一日志系统是项目的核心基础设施，实现了：

1. **统一日志中心**：所有日志通过 `LoggingHub` 统一处理
2. **智能路由分发**：基于四层路由规则引擎，智能决定日志输出目标
3. **性能优化**：规则缓存、进度节流、异步写入、批量数据库操作
4. **不丢失日志**：MemoryHandler缓冲 + 超时机制
5. **有序日志输出**：启动阶段使用有序队列，确保日志按顺序展示

### 1.2 核心特性

- ✅ **四层路由机制**：场景 > 模块 > 阶段 > 全局（从高到低优先级）
- ✅ **7种日志类型**：SYSTEM、PROGRESS、NOTIFICATION、ALERT、USER_FEEDBACK、DEBUG、STAGE_NODE
- ✅ **8种输出目标**：file、console、database、event、event_throttled、ui_statusbar、ui_dialog、ai_file
- ✅ **规则缓存**：LRU + TTL（60秒TTL，5000条缓存）
- ✅ **进度节流**：500ms聚合窗口，减少高频进度日志
- ✅ **异步写入**：AI日志文件使用异步写入队列
- ✅ **批量数据库写入**：批量插入，减少数据库I/O


## 三、核心组件

### 3.1 LoggingHub（统一日志中心）

**文件**: `backend/infrastructure/system_vnpy/unified_log_system.py`

**职责**:
- 拦截所有日志记录（继承 `logging.Handler`）
- 将标准 `LogRecord` 转换为 `UnifiedLogRecord`
- 调用路由引擎进行路由决策
- 根据路由结果分发到不同输出目标

**关键方法**:
```python
class LoggingHub(logging.Handler):
    def emit(self, record: logging.LogRecord) -> None
    def set_stage(self, stage: str) -> None
    def set_scenario(self, scenario: str) -> None
    def set_module(self, module: str) -> None
    def set_event_engine(self, event_engine: EventEngine) -> None
    def set_db_manager(self, db_manager: Any) -> None
```

**单例模式**:
```python
from backend.infrastructure.system_vnpy.unified_log_system import get_logging_hub

hub = get_logging_hub()  # 全局单例
```

### 3.2 RoutingRuleEngine（路由规则引擎）

**文件**: `backend/infrastructure/system_vnpy/unified_log_system.py`

**职责**:
- 加载四层路由规则（场景、模块、阶段、全局）
- 按优先级匹配日志记录
- 返回日志应该输出的目标列表

**路由优先级**:
1. **场景规则**（scenario） - 最高优先级
2. **模块规则**（module）
3. **阶段规则**（stage）
4. **全局规则**（global） - 兜底规则

**关键方法**:
```python
class RoutingRuleEngine:
    def route(self, record: UnifiedLogRecord) -> List[str]
    def _match_scenario(self, record: UnifiedLogRecord) -> Optional[List[str]]
    def _match_module(self, record: UnifiedLogRecord) -> Optional[List[str]]
    def _match_stage(self, record: UnifiedLogRecord) -> Optional[List[str]]
    def _match_global(self, record: UnifiedLogRecord) -> List[str]
```

### 3.3 RuleCache（规则缓存）

**文件**: `backend/infrastructure/system_vnpy/unified_log_system.py`

**职责**:
- 缓存路由结果，避免重复计算
- LRU淘汰策略（最大5000条）
- TTL过期机制（60秒）

**性能优化**:
- 路由耗时（缓存前）: ~0.1ms
- 路由耗时（缓存后）: ~0.01ms
- 缓存命中率: >95%

### 3.4 AILogFileHandler（AI日志处理器）

**文件**: `backend/infrastructure/system_vnpy/unified_log_system.py`

**职责**:
- 异步写入AI日志文件
- 支持流程上下文（`ai_log_process`）
- 自动创建日志文件到 `logs/ai/` 目录

**特性**:
- 异步写入队列，不阻塞主线程
- 支持UTF-8编码
- 自动添加日志级别统计和视觉标识

**使用方式**:
```python
from backend.infrastructure.system_vnpy.unified_log_system import ai_log_process

with ai_log_process("process_name", {"metadata": "value"}):
    logger.info("流程开始")
    # ... 业务逻辑 ...
    logger.info("流程结束")
```

### 3.5 ProgressThrottler（进度节流器）

**文件**: `backend/infrastructure/system_vnpy/unified_log_system.py`

**职责**:
- 聚合高频进度日志（500ms窗口）
- 减少Terminal输出和EventEngine事件
- 提升系统性能

**工作原理**:
1. 收到进度日志时，先检查是否有待发送的记录
2. 如果有，且距离上次发送 < 500ms，则合并（更新进度值）
3. 如果距离上次发送 >= 500ms，则发送待发送记录，并开始新的聚合窗口

### 5.2 配置文件说明

#### 5.2.1 rules_global.yaml（全局默认规则）

**优先级**: 最低（兜底规则）

**作用**: 定义所有日志类型的默认路由策略，所有未被阶段/模块/场景规则覆盖的日志使用此规则。

**主要规则**:
- `SYSTEM.DEBUG`: 仅文件和AI日志
- `SYSTEM.INFO`: 仅文件和AI日志
- `SYSTEM.WARNING+`: 输出到Terminal、数据库、事件
- `STAGE_NODE.INFO`: 输出到Terminal（关键：阶段节点输出到Terminal）
- `PROGRESS.INFO`: 通过事件节流，不输出到Terminal
- `NOTIFICATION.INFO`: 输出到Terminal和状态栏
- `ALERT.WARNING+`: 输出到Terminal、数据库、状态栏

#### 5.2.2 rules_stage.yaml（阶段规则）

**优先级**: 第三优先级

**作用**: 按生命周期阶段切换日志策略。

**定义的阶段**:
- `stage_startup` - 启动阶段（5-10秒）
- `stage_sensing` - 数据感知阶段（10-30秒）
- `stage_downloading` - 数据下载阶段
- `stage_trading` - 交易阶段
- `stage_backtest` - 回测阶段
- `stage_analysis` - 分析阶段
- `stage_idle` - 空闲阶段
- `stage_shutdown` - 关闭阶段

**示例**:
```yaml
stage_startup:
  SYSTEM:
    DEBUG: [file, ai_file]  # 只输出到文件和AI日志
    INFO: [file, ai_file]   # 只输出到文件和AI日志
    WARNING: [file, console, database, event, ai_file]
```

#### 5.2.3 rules_module.yaml（模块规则）

## 六、路由机制

### 6.1 路由优先级

路由引擎按以下优先级匹配规则：

```
场景规则（scenario） > 模块规则（module） > 阶段规则（stage） > 全局规则（global）
```

**匹配逻辑**:
1. 首先尝试匹配场景规则（如果设置了场景）
2. 如果场景规则未匹配，尝试匹配模块规则（如果设置了模块）
3. 如果模块规则未匹配，尝试匹配阶段规则（如果设置了阶段）
4. 如果所有规则都未匹配，使用全局规则（兜底）

### 6.2 日志类型（LogType）

```python
class LogType(Enum):
    SYSTEM = "system"           # 系统日志
    PROGRESS = "progress"       # 进度日志
    NOTIFICATION = "notification" # 通知日志
    ALERT = "alert"             # 告警日志
    USER_FEEDBACK = "user_feedback" # 用户反馈
    DEBUG = "debug"             # 调试日志
    STAGE_NODE = "stage_node"   # 阶段节点日志
```

### 6.3 输出目标（Targets）

- `file` - 常规日志文件（`logs/terminal.log`）
- `console` - 终端输出
- `database` - 数据库存储（SQLite）
- `event` - 事件引擎（EventEngine）
- `event_throttled` - 节流事件（500ms聚合窗口）
- `ui_statusbar` - UI状态栏
- `ui_dialog` - UI对话框
- `ai_file` - AI日志文件（`logs/ai/`目录）

### 6.4 路由示例

**示例1: 启动阶段系统日志**

## 八、性能优化

### 8.1 规则缓存

**实现**: `RuleCache` 类（LRU + TTL）

**性能指标**:
- 路由耗时（缓存前）: ~0.1ms
- 路由耗时（缓存后）: ~0.01ms
- 缓存命中率: >95%
- 缓存大小: 最大5000条
- TTL: 60秒

### 8.2 进度节流

**实现**: `ProgressThrottler` 类

**工作原理**:
- 500ms聚合窗口
- 相同日志类型的进度日志在窗口内合并
- 只发送最新的进度值

**效果**:
- Terminal输出减少: 95.3%
- EventEngine事件减少: 99.3%（300条/秒 → 2条/秒）

### 8.3 异步写入

**实现**: `AILogFileHandler` 类

**特性**:
- 使用 `asyncio.Queue` 异步写入队列
- 后台协程处理写入，不阻塞主线程
- 支持降级到同步写入（如果异步写入失败）

### 8.4 批量数据库写入

**实现**: `LoggingHub` 类中的批量插入机制

**特性**:
- 批量插入缓冲区（默认10条）
- 定时刷新（默认5秒）
- 减少数据库I/O操作

## 九、集成指南

### 9.1 启动阶段集成

**文件**: `backend/startup/stages/logging_init.py`

**步骤**:
1. 使用 `MemoryHandler` 缓冲日志系统初始化前的日志
2. 初始化 `LoggingHub`
3. 创建并注入handlers（console、file、ai_log）
4. 集成有序日志队列（启动阶段）
5. 将LoggingHub添加到root logger
6. 设置MemoryHandler的target为LoggingHub
7. 刷新MemoryHandler，重放缓冲日志
8. 清理所有logger的StreamHandler，确保所有日志都经过LoggingHub

**关键代码**:
```python
from backend.infrastructure.system_vnpy.unified_log_system import get_logging_hub

# 初始化LoggingHub
logging_hub = get_logging_hub()

# 创建handlers
console_handler = logging.StreamHandler(sys.stdout)
file_handler = logging.FileHandler("logs/terminal.log")
ai_handler = get_ai_log_handler()

# 注入handlers
logging_hub.set_console_handler(console_handler)
logging_hub.set_file_handler(file_handler)
logging_hub.set_ai_log_handler(ai_handler)

# 添加到root logger
root_logger.addHandler(logging_hub)
```

### 9.2 服务集成

**在服务中集成LoggingHub**:
```python
from backend.infrastructure.system_vnpy.unified_log_system import get_logging_hub

class MyService:
    def __init__(self):
        self.logging_hub = get_logging_hub()
        
        # 注入EventEngine（如果可用）
        if hasattr(self, 'event_engine'):
            self.logging_hub.set_event_engine(self.event_engine)
        
        # 注入DatabaseManager（如果可用）
        if hasattr(self, 'db_manager'):
            self.logging_hub.set_db_manager(self.db_manager)
```

### 9.3 模块集成

**在模块中使用LoggingHub**:

## 十、启动输出规则

### 10.1 规则概述

启动阶段的日志输出遵循以下硬编码规则：

1. **双重输出**：启动输出既输出到Terminal又输出到 `logs/ai/` 内的log文件
2. **AI日志文件全量写入**：log文件全量写入所有埋线的log（DEBUG及以上所有级别）
3. **Terminal输出分级**：Terminal输出分两种情况：
   - **WARNING、ERROR、CRITICAL**：全量输出到Terminal
   - **正常非WARNING/ERROR/CRITICAL日志**：只输出阶段开始、阶段成果、阶段结束（STAGE_NODE类型）

### 10.2 Terminal输出规则

#### 10.2.1 全量输出（WARNING及以上）

**规则**：所有WARNING、ERROR、CRITICAL级别的日志全量输出到Terminal。

**输出内容**：
- 完整的错误信息
- 完整的异常堆栈
- 警告详情
- 严重问题描述

**示例**：
```
⚠️ 系统资源使用率过高: CPU=85%, Memory=90%
❌ 服务初始化失败: DataCenterService初始化异常
🔥 系统严重错误: 数据库连接失败
```

#### 10.2.2 精简输出（INFO/DEBUG级别）

**规则**：正常非WARNING/ERROR/CRITICAL的日志，只输出阶段节点信息。

**只输出以下内容**：
- **阶段开始**：使用 `📍` 标记，如 `📍 阶段1: 日志系统初始化开始`
- **阶段成果**：使用 `✅` 标记，如 `✅ LoggingHub创建完成`
- **阶段结束**：使用 `✅` 标记，如 `✅ 日志系统就绪 (180ms)`

**不输出**：
- 详细的DEBUG信息
- 常规的INFO日志（除非是阶段节点）
- 中间过程的日志

**实现方式**：
- 使用 `STAGE_NODE` 日志类型标记阶段节点
- 在启动阶段规则中，`STAGE_NODE.INFO` 输出到Terminal
- 其他 `SYSTEM.INFO`、`PROGRESS.INFO` 等不输出到Terminal

### 10.3 AI日志文件输出规则

#### 10.3.1 全量写入

**规则**：AI日志文件（`logs/ai/application_startup_YYYYMMDD_HHMMSS.log`）全量写入所有埋线的log。

**输出内容**：
- **DEBUG**：详细调试信息（如变量值、中间结果）
- **INFO**：常规信息日志（如函数调用、配置加载）
- **WARNING**：警告信息（如资源使用率高、降级运行）
- **ERROR**：错误信息（如初始化失败、异常捕获）
- **CRITICAL**：严重错误（如服务崩溃、数据损坏）

**文件位置**：
```
C:\Users\Administrator\Desktop\terminal_v0.50\logs\ai\
├── application_startup_20251102_103015.log       # 主启动流程
├── monitor_process_startup_20251102_103017.log   # 监控进程启动
└── backend_services_init_20251102_103018.log     # 后端服务初始化
```

#### 10.3.2 文件格式

每个AI日志文件包含：
- **文件头**：流程说明、开始时间、元数据
- **完整日志**：DEBUG及以上所有级别，带图标和分隔线
- **异常堆栈**：完整的Python堆栈跟踪
- **文件尾**：流程结束时间、执行结果、日志统计

### 10.4 启动输出规则配置

#### 10.4.1 阶段规则配置

启动阶段的日志路由规则配置在 `backend/infrastructure/system_vnpy/config/rules_stage.yaml`：

```yaml
stage_startup:
  description: "系统启动和初始化阶段"
  duration: "5-10s"
  SYSTEM:
    DEBUG: [file, ai_file]  # ✅ 只输出到文件和AI日志
    INFO: [file, ai_file]    # ✅ 只输出到文件和AI日志
    WARNING: [file, console, database, event, ai_file]  # ✅ 输出到Terminal
    ERROR: [file, console, database, event, ai_file]    # ✅ 输出到Terminal
    CRITICAL: [file, console, database, event, ui_dialog, ai_file]  # ✅ 输出到Terminal并弹窗
  
  STAGE_NODE:  # 🆕 流程节点
    DEBUG: [file, ai_file]  # ✅ 只输出到文件和AI日志
    INFO: [file, console, ai_file]  # ✅ 阶段节点输出到Terminal（用户需求）
    WARNING: [file, console, database, event, ai_file]
    ERROR: [file, console, database, event, ai_file]
```

#### 10.4.2 全局规则配置

全局默认规则配置在 `backend/infrastructure/system_vnpy/config/rules_global.yaml`：

```yaml
SYSTEM:
  DEBUG: [file, ai_file]  # ✅ DEBUG仅文件和AI日志
  INFO: [file, ai_file]   # ✅ INFO仅文件和AI日志，不输出到Terminal
  WARNING: [file, console, database, event, ai_file]  # ✅ WARNING输出到Terminal
  ERROR: [file, console, database, event, ai_file]    # ✅ ERROR输出到Terminal
  CRITICAL: [file, console, database, event, ui_dialog, ai_file]  # ✅ CRITICAL输出到Terminal并弹窗

STAGE_NODE:
  DEBUG: [file, ai_file]  # ✅ 节点DEBUG仅文件和AI日志
  INFO: [file, console, ai_file]  # ✅✅ 关键：阶段节点INFO输出到Terminal（用户明确需求）
  WARNING: [file, console, database, event, ai_file]
  ERROR: [file, console, database, event, ai_file]
  CRITICAL: [file, console, database, event, ui_dialog, ai_file]
```

## 十一、常见问题

### 11.1 日志没有输出到Terminal

**可能原因**:
1. 当前阶段/场景的规则配置不输出到console
2. 日志级别不够（DEBUG/INFO可能不输出到Terminal）
3. 日志类型不匹配（例如PROGRESS日志默认不输出到Terminal）

**解决方法**:
- 检查 `rules_stage.yaml` 和 `rules_scenario.yaml` 中的规则配置
- 使用 `STAGE_NODE` 或 `NOTIFICATION` 类型确保输出到Terminal
- 使用 `WARNING` 及以上级别确保输出到Terminal

### 11.2 日志没有写入数据库

**可能原因**:
1. 未注入DatabaseManager到LoggingHub
2. 当前规则配置不包含database目标
3. 日志级别不够（DEBUG/INFO可能不写入数据库）

**解决方法**:
```python
# 确保注入DatabaseManager
hub = get_logging_hub()
hub.set_db_manager(db_manager)

# 检查规则配置是否包含database目标
# 通常WARNING及以上级别会写入数据库
```

### 11.3 日志顺序混乱

**可能原因**:
- 并发启动时日志生成顺序与输出顺序不一致

**解决方法**:
- 启动阶段使用 `OrderedLogQueue` 确保日志按顺序展示
- 已集成到 `LoggingInitStage` 中，无需手动配置

### 11.4 性能问题

**可能原因**:
- 规则缓存未生效
- 进度日志未节流

**解决方法**:
- 检查规则缓存统计信息：`hub._routing_engine._rule_cache.get_statistics()`
- 确保进度日志使用 `event_throttled` 目标
- 检查日志频率，避免过高频率的日志输出

### 11.5 如何添加新的路由规则

**步骤**:
1. 确定规则类型（场景/模块/阶段/全局）
2. 编辑对应的YAML配置文件
3. 配置规则条件和目标
4. 重启应用使配置生效

**示例**（添加新的场景规则）:
```yaml
# rules_scenario.yaml
scenario_new_scenario:
  description: "新场景描述"
  SYSTEM:
    INFO: [file, console, ai_file]
  PROGRESS:
    INFO: [file, event_throttled, statusbar]
```
